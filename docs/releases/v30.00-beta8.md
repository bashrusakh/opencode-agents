# v30.00-beta8 — remove dead snippet runtime surface

v30.00-beta8 removes the package `snippet/` layer after applying the same ownership/activation rules used for policies, docs, and commands.

## Runtime-file activation invariant

Every file installed into OpenCode runtime must have a known OpenCode discovery/activation mechanism or a deterministic resident consumer. If a runtime file has neither, it is dead baggage rather than a valid runtime component and should not be shipped.

Human-facing package documentation is outside this rule when it is intentionally not installed into OpenCode runtime.

## Why snippets were removed

The seven files under `snippet/` had no OpenCode auto-discovery path and no root/agent/skill consumer. Their useful runtime semantics were already resident in authoritative owners:

- provenance -> root `AGENTS.md`;
- OCR usage -> `agents/reviewer.md` plus the two OCR skills;
- persistent planning -> root plus `agents/plan.md` / orchestration contracts;
- audit behavior -> root plus `agents/auditor.md`;
- UUPM/UI behavior -> UI role contracts.

The one useful human-only setup detail from `components-json-default-registry-note.md` is preserved in `docs/ui_mcp_setup.md`: the default shadcn registry does not require an extra `registries` entry in `components.json`. The stale MCP JSON example is not retained; the manual setup doc prefers the current official initializer and inspection of generated config.

## Runtime surface

Installed runtime is now intentionally limited to:

```text
AGENTS.md
agents/
skills/
```

The package ships zero custom commands and zero snippets. Human setup documentation and release history remain in `docs/` inside the distribution only.

## Upgrade hygiene

Both installers know the seven historical package-owned snippet filenames. Matching files are backed up and removed during upgrade. Unrelated files in an existing `snippet/` directory are preserved, and the directory is removed only if it becomes empty.

## Unchanged behavior

`AGENTS.md`, all 15 agent prompts, all 13 skills, semantic routing, approval gates, claim authority, state identity, implementation/verification rules, PR provenance, Draft/Candidate/Ready lifecycle, reviewer semantics, and UI behavior are unchanged from beta7.
