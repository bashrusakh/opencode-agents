# OpenCode Agent Pack v30.24 beta

## Scope

Small authority-provenance wording refinement over v30.23. Runtime semantics stay in the same model: derived reasoning is evidence until its authority is established, and necessary technical consequences may cross implementation layers without creating stronger requirements.

## Prompt-design basis

The wording was rechecked against the current OpenAI prompting guidance:

<https://developers.openai.com/api/docs/guides/latest-model>

<https://developers.openai.com/api/docs/guides/prompting>

The relevant guidance is to keep prompts lean, state an instruction once, use plain language and precise verbs, define autonomy/scope boundaries clearly, and validate prompt changes on representative cases.

## Changes

- Root §2.2.1 now gives an explicit counterfactual necessity test: a technical consequence is necessary only if leaving it out would make the established outcome fail.
- Root §2.2.1 says to judge necessity against the established outcome rather than against a broader rule inferred during planning, implementation, testing, or review.
- `code-orchestrator` handoff fields now name any material claim that is still only evidence or a hypothesis.
- `code-orchestrator` explicitly prevents such a claim from being passed to a specialist as acceptance.

## Review guard

The existing reviewer rule remains the canonical review-side application: a review finding is evidence rather than new authority, and downstream consequences of a broader inferred rule are not automatically current-scope fixes. It is intentionally not duplicated elsewhere.
