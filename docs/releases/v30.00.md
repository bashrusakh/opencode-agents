# v30.00 — Stable runtime simplification

v30.00 is the stable successor to v28.42. The goal is to reduce duplicated policy and dead runtime surfaces while preserving the behavioral contracts that protect routing, scope, state identity, correctness, verification, and publication.

## What changed

- Runtime is reduced to `AGENTS.md`, `agents/`, and `skills/`; package custom commands and snippets are no longer shipped.
- Root policy keeps cross-role invariants and routing; execution-specific rules stay with the roles that own them.
- Repository state/provenance and the owned-PR Draft → Candidate → Ready lifecycle are consolidated around one authoritative state model.
- Natural-language semantic routing replaces package slash-command aliases without removing their underlying capabilities.
- Human setup guidance for UI MCP/UUPM remains in `docs/` but is not installed as runtime policy.
- `agents/code-orchestrator.md` is retained exactly from v28.42 because behavioral testing showed that compressing its role-local contract changed model routing behavior.
- Installers remove only known package-owned legacy surfaces and preserve unrelated user/project files.

## Why

The v28.x package accumulated several copies of the same workflow rules across root policy, role prompts, commands, snippets, and reference docs. v30.00 makes ownership explicit: rules that must exist before role selection remain resident, while role-specific mechanics live in their owning agents. Files without a deterministic OpenCode activation path are not shipped as runtime surfaces.

The result is a smaller package with fewer competing instructions while retaining the proven correctness and orchestration behavior from v28.42 where model testing showed that local enforcement matters.
