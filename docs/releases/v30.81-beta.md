# v30.81 beta — UI routing discriminator hardening

## Purpose

v30.81 beta fixes one bounded orchestration defect observed after the v30.80 stable promotion: `code-orchestrator` already had good leaf-handoff contracts for both `@ui-implementer` and delegated `@ui-orchestrator`, but it could still collapse an unresolved UI/UX direction into a parent-authored implementation recipe before choosing the role.

The motivating failure class is generic: a user establishes the functional/user-visible requirement but rejects the current presentation and asks the workflow to decide how the replacement should look or behave. The orchestrator must not treat that as a settled UI outcome merely because the functional requirement is known.

## Runtime semantic change

Only `agents/code-orchestrator.md` changes semantically.

Before selecting a UI leaf, it now distinguishes:

- **settled user-visible outcome** — material presentation/interaction choices are already established by the user, an adopted plan, or a sufficiently specific existing project pattern; focused direct `@ui-implementer` work remains valid;
- **unresolved presentation/interaction direction** — materially different layout, information hierarchy, disclosure, interaction, or error-state treatments remain, or user feedback rejects the current treatment without adopting a replacement; the bounded UI domain routes to `@ui-orchestrator` instead of being pre-solved by the code orchestrator.

This does not add a new UI workflow owner, duplicate `ui-orchestrator` leaf-handoff rules, or require ceremonial UI planning for every frontend edit. It closes the routing discriminator between two already-established paths.

## Regression coverage

- `role-handoff-audit.py` adds a high-risk `code-orchestrator → ui-orchestrator` profile covering the settled-vs-unresolved discriminator and the prohibition on parent-authored UI direction laundering.
- `role-handoff-selftest.py` adds a synthetic negative in which rejected UI feedback is converted into exact parent-selected copy/placement and sent directly to `@ui-implementer`; that fixture must fail the edge audit.
- ST-79 adds an end-to-end semantic transition scenario for the same failure class and includes the preservation counterexample: direct `@ui-implementer` remains correct when the user/adopted plan/project pattern has already settled the material UI treatment.
- Static policy regressions bind the runtime discriminator and ST-79 without treating static presence as behavioral replay proof.

## Evidence limits

Contract/static/handoff checks establish that the rule and regression harness are present and internally consistent. Fresh isolated behavioral replay of ST-01…ST-79 remains a separate evidence class and is not claimed by this release.
