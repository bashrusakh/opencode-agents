# v30.17 beta

Semantic readiness-authority alignment built on v30.16 beta.

## Why

The pack already ranked current normalized user intent above task-specific workflow rules and already recognized that some remote checks are unavailable while a PR remains Draft. A fixed orchestration recipe still presented `remote CI/status -> Ready` as a universal order, while root wording could be read as elevating every readiness/verification evidence condition called “mandatory” into a prohibition. A weaker model could therefore mistake lifecycle-dependent evidence for a failed prerequisite and then use the pack's own evidence rule to refuse an otherwise authorized state transition.

## Changes

- Root §4 now states explicitly that tests/CI/readiness evidence is state rather than independent authority, and that pack readiness/verification evidence conditions keep their section-0 priority even when described as mandatory. Missing evidence still blocks the default pack workflow, but cannot self-elevate above a conflicting higher-priority instruction. Separate ownership/capability/destructive/publication boundaries keep their existing rules.
- Once a pack-level readiness/verification evidence gap is known, a user's explicit instruction to perform the same already-authorized action anyway is treated as the priority conflict itself; no magic `override`/`waive` wording is required.
- Adds a semantic non-circular-gate invariant: a condition is a precondition only when it can legitimately be satisfied before the gated action in the actual repository/process. Evidence that becomes available only after crossing that boundary is evaluated where it can exist rather than being converted into a self-blocking failure.
- Higher-priority project policy remains authoritative. If project policy itself appears circular/contradictory and exposes no valid path, the workflow reports that policy conflict rather than inventing an override.
- `code-orchestrator` no longer encodes one universal `remote CI/status -> Ready` final order. Final readiness is dependency-driven while Candidate HEAD, Base SHA, whole-PR review, remote-head identity, and base-drift reconciliation stay intact.
- `pr-readiness` now classifies remote CI/status by actual lifecycle availability and warns that a host status token is evidence of state rather than a semantic verdict by itself. Ready conditions are applied by dependency, not list order.
- `verification-strategy` and the reviewer-verdict Draft rule now label their blocking behavior as the default pack readiness contract, preserving the evidence gap without turning it into higher authority than root §0/§4.

## Unchanged

- Project-local authoritative rules remain above user intent in the root priority hierarchy.
- Safety/runtime/tool constraints and hard role-capability ceilings remain non-waivable.
- Candidate HEAD / Base SHA identity, whole-PR reviewer coverage, provenance, repository-prerequisite semantics, base-drift freshness, and unowned-PR protections remain unchanged.
- No agent topology, permissions, installer, or bundled-skill inventory changes.
