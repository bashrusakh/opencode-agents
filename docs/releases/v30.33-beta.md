# v30.33 beta

## Purpose

Separate pre-mutation semantic gating from post-hoc instruction diagnosis, and make the evaluator taxonomy operationally distinguish missing evidence from missing or violated instructions.

## Changes

- Adds `agents/semantic-checkpoint.md` as a read-only delegated gate between material read-only discovery and edit-capable implementation.
- Runs the checkpoint only when a candidate direction materially establishes or changes required behavior, acceptance, scope, ownership, invariant, fix level, or product/domain policy. Routine implementation mechanics remain with implementation roles.
- Uses only `proceed`, `hold`, and `unverified` checkpoint verdicts. The checkpoint reports authority and factual evidence separately and has no post-hoc failure taxonomy.
- Keeps `agents/session-evaluator.md` diagnostic-only after workflow completion. It includes participating checkpoint sessions in the audited tree while excluding evaluator retries.
- Separates `unverified` evidence status from confirmed post-hoc finding classes. Missing task evidence, missing artifact contents, incomplete history, or unknown historical instruction text no longer satisfy `instruction-gap`.
- Defines `instruction-violation` for material semantic/authority/scope/acceptance/gate decisions that contradict a clear applicable rule even when a reasoning mistake caused the violation.
- Reserves `execution-error` for ordinary factual, implementation, tool, evidence-handling, sequencing, or operational mistakes that do not themselves redefine the semantic contract.
- Keeps the new behavior role-local: root claim-authority policy remains canonical and is not duplicated into a second global semantic rule set.
