# v30.71 beta — README topology and canonical-owner cleanup

## Summary

v30.71 changes documentation, not runtime agent/skill behavior. README is restructured as a usage/navigation surface so it no longer acts like a second workflow policy.

## Changes

- Makes `code-orchestrator` explicit as the normal top-level owner for multi-step coding, bugfix, PR-follow-up, CI-repair, and release-preparation workflows.
- Separates top-level workflow owners from delegated specialists instead of presenting semantic leaf owners as equivalent user entrypoints.
- Removes duplicated Startup template, owned-PR lifecycle/state sequence, verification cadence, semantic-role procedure, and release-validation checklist from README.
- Replaces duplicated policy prose with links to the canonical owner: `AGENTS.md`, role contracts, skills, or semantic-design manual.
- Keeps README focused on package purpose, entry-role selection, execution topology, package contents, installation, documentation navigation, and current release summary.

## Semantic intent

README is informational. It must help a user choose the correct workflow owner without defining a parallel routing/state-machine/validation policy. Detailed policy remains canonical in `AGENTS.md`, executable role method remains in `agents/`, and release methodology/checklists remain in `docs/semantic-design-manual.md`.

Runtime agent files and bundled skill files are unchanged from v30.70. Root policy is unchanged except for the pack-version marker.

## Validation-shape correction

The static README release-identity guard now checks the semantic invariant (the active release-note path is referenced) rather than requiring the old `Documentation map` table rendering. This allows README information architecture to change without weakening release identity checks or forcing obsolete layout back into the document.
