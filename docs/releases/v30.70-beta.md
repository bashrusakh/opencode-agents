# v30.70 beta — role lifecycle and closed-world topology gates

## Purpose

v30.70 prevents a routed agent from becoming operationally "naked" through topology, ownership, or prompt-compaction changes after it once passed review. Runtime agent contracts remain unchanged from v30.69.

## Process hardening

- A role PASS is requalified when delegation topology/mode/caller coverage expands, substantive responsibility/proof moves into the role, or an advisory/reference relationship becomes mutation/verdict/workflow ownership.
- Canonical-owner deduplication now requires method preservation: the receiving role must retain an executable core loop, conditional decisions, false-success defense, evidence threshold, stop/escalation and result semantics after duplicate prose is removed elsewhere.
- `role-handoff-audit.py` discovers pack-owned `@role` relations from root plus every standing agent contract and compares them with a closed-world classification inventory. Unknown edges and stale classifications fail release. Classification is topology evidence only; material delegation edges still require protocol checks.
- `contract-protocol-selftest.py` now proves that a new agent without an audit profile and a stale role profile fail. `role-handoff-selftest.py` proves that new unknown edges, stale edges and invalid edge classes fail.

## Why this is needed

Historical role evolution could change execution topology or move procedures between layers while reviewers focused on duplication/ownership cleanliness. That allowed a role to inherit more responsibility without being requalified as an executable interface. v30.70 makes requalification a lifecycle invariant rather than an incident-specific reminder.
