# v30.6 beta — remove server-incompatible binary-upload integration

v30.6 beta removes the bundled GitHub binary-upload integration introduced during the visual-evidence experiments. Its credential-dependent runtime model is unsuitable for the intended server environment.

## Changes

- Removes the bundled binary-upload skill and its license/vendor files.
- Removes its root skill-catalog entry, runtime activation hook, README integration text, upstream attribution, and historical package references.
- Removes the dedicated intermediate release note that existed only to document that integration.
- Bundled inventory is now 18 skills: 13 specialist/advisory and 5 workflow/policy skills.
- Visual-evidence publication remains transport-agnostic: use only a mechanism already available and authorized in the current environment.
- If no valid binary publication mechanism is available, preserve the local evidence and report publication as blocked.
- Do not invent gist/branch/ref/commit/tag hosting as an implicit fallback.

## Unchanged

- Resource lifecycle and final reconciliation states.
- Gated deletion of remote/published/shared resources.
- Entry-routing vs delegation-routing topology.
- Explicit fallback semantics.
- Plan permissions and portable planning paths.
- All 15 agent roles and their frontmatter modes/permissions.

## Validation target

The release must contain no runtime or documentation hook for the removed uploader; all 18 remaining skills must be installed, discoverable, and correctly activated where required.
