# v30.74 beta — semantic role-contract shape standardization

## Purpose

v30.74 standardizes how role contracts are designed and audited without forcing cosmetic prompt uniformity. Runtime agent and skill contracts remain unchanged from v30.73.

## Standardized semantic shape

The existing `docs/semantic-design-manual.md` now names five role-contract functions:

1. **Ownership** — capability/stage ownership and adjacent-role boundary.
2. **Invocation** — assignment meaning: target/state/mode/action ceiling and authority/constraint/evidence/hypothesis classes when material.
3. **Method** — characteristic role-owned action/decision loop plus false-success/adversarial defense.
4. **Boundaries** — stop/blocker/escalation/reroute and unavailable-evidence handling.
5. **Result** — what output proves, its evidence/coverage limits, unknowns, and safe caller inference.

The preferred reading order is `Ownership → Invocation → Method → Boundaries → Result`, but this is explicitly **not** a five-heading template. Compact roles may merge functions; orchestrators may split Method across routing/workflow/evidence sections; verdict roles may express Invocation through target/evidence sections. No duplicate summary is added merely for visual uniformity.

## Current-role audit

All 17 current roles were manually mapped to the five functions. Every role has a clear primary locus for each function, so no runtime prompt was rewritten solely for heading consistency. Existing contract/protocol and closed-world handoff gates remain green.

## Semantic regression

ST-64 requires semantic-function preservation instead of heading conformity: a compact role with clear merged functions may pass, while a role with perfect headings but no executable method must fail.
