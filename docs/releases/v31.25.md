# v31.25 candidate — Open Code Review skill refresh

**Status:** Candidate. The two bundled Open Code Review advisory skills are refreshed against upstream `main`; candidate structural/package gates are required. No real-model behavioral replay is claimed.

## Summary

Updates only the package-integrated skill content for Alibaba Open Code Review and the corresponding vendor-skill provenance hashes. The integration remains subordinate to the pack's reviewer role and root policy.

### `open-code-review`

- Fresh `--commit` and `--from` reviews run Review and behavior/impact Analysis together with `--analysis` by default. Workspace, preview, resume, SARIF, and explicitly no-analysis requests remain outside this default.
- JSON is the default combined-output format for agent consumption unless another supported format is requested; the original repository, refs, background context, and output path must be preserved.
- Review findings/coverage and Analysis are reported separately. The instructions identify the `ocr.review-with-analysis/v2` schema, `analysis_meta.execution_status`, `analysis_meta.declared_completion`, and Analysis-only token budget reporting. Missing combined metadata means Analysis is unverified, not implicitly successful.
- A clean-review claim requires coverage evidence. Mispositioned comments (`start_line` and `end_line` both zero) are investigated from their content/context; unresolved positions are reported at file level rather than assigned invented line numbers.

### `open-code-review-delegate`

- The host reviewer checks which existing callers or user workflows behave differently, comparing the exact target sides already obtained by the pack's Step 4. Evidence gathering remains bounded and reuses collected context.
- A deleted file's old side may be consulted as context when the deletion is relevant, but it is not counted as reviewed. Other preview exclusions remain respected.
- Material intentional behavior changes are reported separately from severity-rated defects and coverage, with affected workflow, before/after behavior, and supporting location. Uncertain impacts are qualified; no empty impact section is required.

## Ownership and compatibility decisions

- `agents/reviewer.md` remains the owner of activation and review authority. No change makes native OCR automatically mandatory or changes the existing mandatory deterministic delegate-preflight contract.
- The delegate skill remains preflight plus host-review procedure; it does not acquire mutation authority. The upstream optional Fix step is intentionally not imported because fixes remain governed by the active pack workflow and reviewer authority.
- The upstream skill's standalone native-versus-delegate selection text is not copied into the skill frontmatter: mode activation remains owned by the pack's reviewer role and current workflow policy.
- Local step numbering is preserved. The upstream delegate Step 4 review behavior maps to this pack's Step 5 (host reviewer performs substantive review), because local Step 4 is the preceding exact-diff/content acquisition step. Upstream Step 6 reporting maps to local Step 6.
- No agent, role, permission, semantic owner, workflow stage, model routing, or publication rule changes.

## Validation boundary

Candidate gates validate structural contracts, manifests, installer behavior, and package integrity. They do not prove that every model/runtime execution will follow the revised review method. No isolated live-model replay is claimed. Promotion additionally requires a source-aware prior-release preservation review and the applicable release gates.
