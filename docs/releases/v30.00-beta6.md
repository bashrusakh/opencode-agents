# v30.00-beta6 — semantic command-layer cleanup

v30.00-beta6 removes the parallel slash-command routing layer that duplicated natural-language semantic routing.

## Command ownership rule

A custom command is justified only when invoking the command adds a mechanism or procedure that natural-language routing plus the owning agent contract does not already provide. A command must not be a shorter or second normative version of an agent.

Therefore 19 semantic aliases are removed:

- `audit`
- `bug-issue`
- `bugfix`
- `code-explore`
- `debug`
- `devops-check`
- `execute-plan`
- `plan`
- `pr-followup`
- `pr-provenance`
- `release-prep`
- `review`
- `ui-a11y-check`
- `ui-audit`
- `ui-implement`
- `ui-options`
- `ui-plan`
- `ui-redesign`
- `verify`

Their behavior remains available through resident `AGENTS.md` semantic routing and the relevant agent contracts. No correctness rule is owned only by a removed command.

## Remaining commands

Only two procedural setup commands remain:

- `/ui-mcp-setup` -> `@devops`
- `/ui-uupm-setup` -> `@devops`

They are self-contained command procedures and use `subagent: false`. Their former setup documents are deleted; `docs/` now contains release history only.

## Routing coverage added during reverse audit

Deleting aliases exposed three intents that deserved explicit resident routing rather than a slash shortcut:

- accessibility/keyboard/focus/form/interaction review of an implemented UI target -> `@a11y-reviewer`;
- branch/PR provenance-only inspection/proof -> `@code-orchestrator`;
- execution/resumption of an authorized persistent coding-plan work package -> `@code-orchestrator`, while preserving UI/DevOps domain routing when applicable.

These are routing rules needed before a role is selected, so root is their correct owner.

## Upgrade hygiene

The install scripts back up and remove exact package-owned filenames for obsolete semantic commands and removed package docs before installing the current runtime set. They do not delete unrelated user/project command or documentation files.

Package release notes remain under `docs/releases/` but are not copied into OpenCode runtime config by the installers.

## Unchanged invariants

No change is intended to approval gates, claim authority/semantic correspondence, Startup/state identity, mutation/right-level/regression rules, verification cadence, PR provenance semantics, Candidate/Ready lifecycle, agent permissions/modes, or skill behavior.
