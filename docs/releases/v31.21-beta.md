# v31.21 beta — Safe task-scoped recovery across provider limits

## Changes

1. **Material-progress persistence (`workflow-control`).** For activated durable planning, update the canonical task state after significant completed work-package/phase or changed decision, blockers, review disposition, evidence freshness, or next safe action. When GrayMatter continuity is available, checkpoint that state at meaningful boundaries and before an anticipated provider-limit interruption; group minor fixes, avoid timed/polling and per-tool saves.
2. **Task-scoped GrayMatter checkpoints (`graymatter-memory`).** Preserve the existing project/role `agent_id` for durable knowledge, but save/resume *transient* checkpoints under a stable task-specific namespace. Resume checks the project and task, then reconciles Git/ref/SHA/worktree and evidence freshness against canonical state and actual environment. Repository-wide latest checkpoints from other tasks are never silently substituted.

## Boundary

Checkpoint state is not semantic authority, and no verification claim survives an incompatible candidate state. The same reviewer independence, activation gates, repository mutation authorization, and fallback project planning convention remain in force. No new agent, skill, test, mandatory artifact, or workflow stage. Actual provider-limit resilience and runtime GrayMatter availability require observation in real sessions.
