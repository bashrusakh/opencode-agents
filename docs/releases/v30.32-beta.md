# v30.32 beta

## Purpose

Clarify claim-level authority when the user explicitly adopts an external artifact as the task or specification.

## Changes

- When the user explicitly adopts an issue, plan, RFC, review, document, or other artifact as the task/specification, its requested outcomes, acceptance criteria, and explicit constraints are treated as part of established user intent unless higher authority conflicts.
- Factual diagnoses, implementation claims, and proposed mechanisms inside the same artifact remain evidence that must be verified under the existing claim/evidence rules.
- Release validation names these tests as semantic invariant checks and requires them to exercise general rules rather than incident-specific wording.
