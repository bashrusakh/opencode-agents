# v30.93 beta — whole-pack skill ownership and typed-domain control

## Summary

v30.93 extends the v30.92 semantic control plane from the root/role graph into the package-owned skill layer while deliberately leaving third-party skill content unchanged.

The release treats bundled skills as three provenance classes:

- **pack workflow owner** — conditional workflow procedure owned by this pack;
- **pack integration** — pack-owned adapter/ordering/tool procedure around an external/runtime capability;
- **vendor advisory** — third-party skill content preserved as upstream/provider guidance and subordinate to pack-owned integration/authority rules.

## Runtime ownership corrections

- Root `AGENTS.md` now canonically owns the contemporaneous provenance-receipt field interface. `code-orchestrator` owns when the receipt must be produced; `session-evidence` owns retrieval/consumption mechanics.
- `persistent-planning` now owns fallback durable representation, resume/update, and work-package persistence mechanics only. Root §2.3 remains the activation/canonical-state owner.
- `graymatter-memory` now owns GrayMatter identity, query, checkpoint, durable-write/correction, and tool-call mechanics only. Root remains owner of memory authority, activation, freshness/independent-judgment isolation, and durable-vs-transient semantics.
- `verification-strategy` now owns verification-layer selection, batching/cadence, independent tester activation, and blocked-boundary handling. Root §7.4 retains universal evidence validity/freshness and anti-pass-manufacturing rules; `tester` retains execution/reporting method.
- Vendor OCR/UUPM content is not rewritten. Pack-owned integration boundaries explicitly prevent vendor descriptions/body text from taking ownership of review method, managed-review activation, mutation gates, project source-of-truth, or design-system persistence.

## Control-plane additions

- `evals/skill-control-spec.json`
- `evals/skill-control-audit.py`
- `evals/skill-control-selftest.py`

The skill-control manifest exactly classifies all 22 bundled entrypoints, inventories pack-controlled top-level procedure sections, cross-checks pack skill owner/consumer/domain declarations, and hash-guards all 13 vendor skill directories.

Semantic ownership now declares 28 material shared capabilities. The ownership audit also scans declared pack-controlled skills for guarded shared-family redefinition, so a behaviorally consistent skill-side duplicate can fail promotion even when role behavior remains green.

Typed domains now include:

- evidence status: `established | unverified | contradicted`;
- proposition relation: `preserved | refined | strengthened | weakened | substituted | indeterminate`;
- semantic-checkpoint verdict: `proceed | hold | insufficient-context`;
- trajectory verdict: `continue | reanchor | reassess | checkpoint-required | insufficient-evidence`;
- resource-lifecycle terminal state: `cleaned | intentionally retained | cleanup blocked | ownership transferred`;
- owned-PR lifecycle state: `Draft | Candidate HEAD | Ready`.

The domain audit discovers verdict enums in roles and declared pack-controlled skills; vendor-advisory content is not promoted into the pack type system.

## Evaluation changes

Adds:

- **ST-123** — pack-owned skill cannot become an undeclared second semantic owner;
- **ST-124** — typed semantic collision inside a pack-owned skill is a release failure;
- **ST-125** — vendor skill content remains subordinate to the pack integration boundary;
- **ST-126** — root-owned canonical state and skill-owned procedure must not collapse into duplicate policy.

Structural/static/ownership/domain/skill-control mutation checks are release evidence. Fresh isolated behavioral model replay remains a separate evidence class and is not claimed unless actually run.

## Explicit non-change

Agent permission/frontmatter policy is unchanged. All third-party skill directories listed in `THIRD_PARTY_NOTICES.md` are byte-identical to v30.92 in this release.
