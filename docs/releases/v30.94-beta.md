# v30.94 beta — runtime residency and conditional shared contracts

## Summary

v30.94 separates **semantic ownership** from **instruction residency**. A rule may have one correct canonical owner and still be resident at the wrong disclosure level. The global `AGENTS.md` is now the universal semantic kernel; workflow-entry, delegation-caller, and implementation/judgment procedure load only for invocations that need them.

This release deliberately does **not** change agent permission/frontmatter policy and does **not** edit bundled third-party skill content.

## Residency split

Three pack-owned shared contracts are added with `opencode/autoinvoke: "false"`:

- `workflow-entry` — primary/user-facing request normalization, Startup/Update, user-approvable gates, durable-planning activation, repository/publication ownership and final workflow reporting;
- `delegation-control` — caller-side handoff, decision-space preservation, fresh-child/independent-judgment isolation, routing/fallback, evidence reuse/review cadence and workflow-created-resource reconciliation;
- `implementation-contract` — behavioral contract, pre-mutation/provenance baseline, right-level implementation boundary, regression guard, verification freshness and read-only implementation judgment.

Role contracts activate those skills by the **current invocation**. Primary-only ownership is not inferred from `mode: all`: delegated `build`, `ui-orchestrator`, `librarian`, and `project-planner` skip primary/caller contracts unless their role contract explicitly activates one for that invocation. Leaf roles cannot regain owner contracts through auto-selection.

## Universal root

The always-loaded root retains only semantics justified for every role:

- precedence and hard capability ceilings;
- source-of-truth/continuity and memory-as-capability boundary;
- task-semantic authority/evidence/proposition relation and provenance receipt interface;
- skill/vendor authority containment;
- communication and evidence-bound final claims;
- role/capability/assignment boundaries;
- short conditional-contract activation ownership rules.

Detailed request routing, Startup blocks, caller handoff construction, fresh-child procedure, review cadence, implementation mutation/regression procedure, and repository/publication owner procedure are no longer universal standing context.

## Control-plane changes

Adds:

- `evals/runtime-residency-spec.json`;
- `evals/runtime-residency-audit.py`;
- `evals/runtime-residency-selftest.py`.

The residency gate is separate from semantic ownership and section placement. It checks that caller/implementation/resource-specific procedure is absent from global root, conditional shared contracts cannot auto-invoke, and role-local activation matches primary/delegated/conditional invocation boundaries.

The semantic design method now records audience/residency classes independently from canonical owner: `universal`, `primary-entry`, `delegation-caller`, `implementation/judgment`, `role-local`, `conditional-skill`, and `vendor-advisory`.

## Evaluation changes

Adds:

- **ST-127** — correct ownership does not justify universal residency;
- **ST-128** — a delegated `mode: all` invocation must not inherit primary-owner contracts;
- **ST-129** — implementation procedure must be conditional without disappearing from applicable implement/judge roles.

Existing semantic-owner, typed-domain, section-placement, role-executability, handoff, static, installer and skill-control gates are recomposed against the conditional shared contracts rather than requiring old root-local text.

Structural/static/mutation evidence does not substitute for fresh isolated behavioral replay. v30.94 therefore remains beta unless ST-127..ST-129 are separately replayed.

## Explicit non-change

- Agent permission/frontmatter policy is unchanged.
- All 13 third-party/vendor skill subtrees are preserved byte-for-byte from v30.93.
- Resource-specific `code-orchestrator` pipelines such as GitHub PR/issue/release handling are **not** moved in this release; their own residency is the next design question after the root split.
