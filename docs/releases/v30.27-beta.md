# v30.27 beta

## Purpose

Add a temporary post-hoc semantic evaluation harness for developing and validating the agent pack itself. The evaluator audits a completed `code-orchestrator` workflow and its child-agent calls against the instructions and authority that governed them. It does not re-review or modify the completed implementation.

## Runtime changes

- Adds `agents/session-evaluator.md` as a read-only delegated diagnostic role.
- Adds `tools/session_trace.js`, which derives the evaluator's parent session from its own OpenCode session context, lists the parent/child session tree, excludes diagnostic evaluator sessions, and exposes paged projected messages for sessions in that tree.
- Adds a temporary root trigger after non-trivial `code-orchestrator` completion. The audit runs once before the final report and cannot reopen, modify, publish, or gate the completed work.
- Installers now copy the diagnostic tool to the OpenCode `tools/` directory and preserve an existing same-name tool in the normal backup surface before global overwrite.

## Evaluator contract

The evaluator reconstructs the causal chain from authoritative task to final workflow state and checks material framing, behavior, scope, ownership, invariant, fix-level, delegation, role, verification, gate, and publication decisions. It treats prior agent conclusions as claims/evidence, traces each problem to its earliest material divergence, and distinguishes later locally reasonable work from the bad premise it inherited.

Confirmed findings use one class:

- `instruction-violation`
- `instruction-ambiguity`
- `instruction-gap`
- `execution-error`
- `justified`

`unverified` is an evidence status, not a finding class. Prompt changes are candidates only for confirmed reusable ambiguity/gaps not already covered by the contract.

Historical instruction provenance is time-local: current instruction files are not assumed to have governed earlier actions. If the governing instruction set cannot be established from trace/repository evidence, the affected conclusion remains `unverified` rather than being labeled an ambiguity or gap.

## Prompt-design basis

The evaluator is deliberately bounded and read-only. Its prompt uses one purpose, explicit evidence sources, concrete finding classes, causal attribution, and a fixed output contract. It avoids a generic self-critique loop, avoids re-running ordinary implementation review, and obtains the session trace independently. This follows current guidance to keep prompts lean, state instructions once, use concrete verification criteria, and evaluate agent transcripts/outcomes rather than relying only on final answers.

## Compatibility note

`session_trace` uses the current OpenCode V2 session HTTP API through `opencode api` and is therefore an experimental diagnostic surface. If that API/CLI surface is unavailable, the evaluator must report the trace as unavailable rather than guessing from a parent summary.
