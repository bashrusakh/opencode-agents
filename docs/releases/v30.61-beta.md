# v30.61 beta

## Changes

- Root task-semantic authority now states explicitly that an authoritative implementation mechanism is only an implementation constraint. It is not evidence that the candidate is correct, sufficient, right-level, maintainable, performant, secure, or regression-free, and it does not authorize collateral degradation/tradeoffs unless those are separately established.
- Fresh independent-judgment context isolation now carries task-contract propositions and separately established implementation constraints without framing the selected candidate mechanism as accepted design, adequacy proof, or a waiver of collateral regressions.
- `code-orchestrator` operationalizes that handoff boundary for fresh whole-change/final reviewer assignments and uses `expected deliverable/evidence` rather than ambiguous `expected result/evidence`.
- `reviewer` now makes independent judgment explicit: requested/selected mechanisms do not suppress normal correctness, preserved-behavior, wrong-fix-level, maintainability, security, performance/resource, or regression findings. A separately accepted degradation/tradeoff is honored only within its exact accepted envelope.
- `reviewer` generalizes performance/resource regression review beyond critical-section-only paths and makes material workaround/wrong-fix-level findings explicit while preserving an evidence-based, non-ritual benchmark standard.
- `session-evaluator` audits mechanism-as-correctness framing and collateral-tradeoff laundering in independent reviewer handoffs.
- Adds ST-33 and ST-34 plus static structural guards.
