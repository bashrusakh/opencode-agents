# v30.39 beta

## Purpose

Preserve the semantic-authority improvements already present in v30.38, add compact model-agnostic communication rules derived from current developer guidance, document the semantic-design methodology, and remove the v30.37 provenance-lineage workaround whose motivating failure was later traced to an OpenChamber runtime pagination defect.

## Runtime changes

### Root `AGENTS.md`

The v30.38 claim-level authority rules remain unchanged. Communication now has three explicit bounds:

- Startup is the only routine pre-tool narration; do not add a second prose plan around it.
- During tool work, update the user only for a material finding, blocker, or meaningful change of direction, and keep the update to the finding/change plus the next action.
- Final and delegated reports contain only material results and evidence needed by their recipient; empty categories, repeated context, and routine process narration are omitted.

### `semantic-checkpoint` and `session-evaluator`

The v30.37 predecessor/ancestor provenance expansion is removed. Both roles retain the v30.36 complete-parent/material-session retrieval contract and all v30.38 semantic-delta/authority checks.

The reason is causal, not stylistic: the reproduced missing-history failure came from OpenChamber `session.messages(all:true)` returning only one paginated OpenCode message page. A runtime retrieval defect should be fixed in the runtime rather than compensated for by broadening semantic session traversal.

### Documentation

Adds:

- `docs/semantic-design-manual.md` — a model-agnostic method for converting developer guidance, traces, and project requirements into durable semantic rules;
- `docs/semantic-design-source-audit.md` — a source-preservation matrix and reverse-derivation checks verifying that the original actionable consequences remain derivable after abstraction.

## Preserved v30.38 semantics

The release intentionally keeps:

1. user authority bounded to the material proposition actually presented for decision;
2. semantic correspondence and qualifiers across questions, summaries, plans, assignments, checkpoints, and handoffs;
3. conditional/fallback status until its premise is established;
4. the requirement for a blocker or separate authority before replacing a viable stronger established outcome with a weaker one;
5. role-specific semantic-delta checks in `code-orchestrator`, `semantic-checkpoint`, and `session-evaluator`.

## Non-changes

- No new agent, skill, command, tool, or mandatory workflow stage.
- `code-orchestrator` keeps the v30.38 semantic-authority changes unchanged.
- Fresh-child checkpoint/session-continuity rules remain unchanged.
- The semantic manual is documentation, not a second runtime policy source.
- No provider/model-specific routing is introduced.
