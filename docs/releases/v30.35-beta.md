# v30.35 beta

## Purpose

Make child-session continuity explicit and role-correct so independent judgments do not inherit hidden conversational state from earlier specialist runs, while genuine same-workstream continuation can still reuse context deliberately.

## Runtime change

Two runtime policy locations change.

### Root delegation policy

`AGENTS.md` now makes session continuity follow **assignment continuity**, not agent identity:

- a new specialist assignment starts in a fresh child session;
- a new review, verification, gate, or other independent judgment over a new/materially changed candidate or state starts in a fresh child session;
- a returned child may be continued only when the parent is deliberately continuing the same specialist-owned workstream and that accumulated context is still part of the same assignment;
- calling the same role again is not, by itself, a reason to reuse its previous child session.

This is intentionally not a blanket “always fresh” rule. Long-running exploration, implementation, debugging, or planning may legitimately benefit from continuity when the assignment itself is continuing.

### Semantic checkpoint application

`code-orchestrator` now requires every `semantic-checkpoint` verdict to run in a **fresh child session**, including re-checks after `hold`, `unverified`, new authority/evidence, or a materially changed candidate.

The orchestrator may carry prior checkpoint blockers as diagnostic workflow evidence, but it must not continue the prior checkpoint conversation or treat that prior reasoning as authority for the next verdict. The fresh checkpoint reconstructs the current candidate from authoritative task/session evidence.

## Why this boundary

The motivating live workflow showed multiple checkpoint turns in one child-session history. That defeats the intended independent-gate property: a later verdict can inherit the earlier checkpoint's own framing, blockers, or conclusion as conversational state even though the checkpoint contract says prior checkpoint reasoning is not task authority.

OpenCode V2 documents `subagent` execution as fresh-context child sessions and makes same-child continuation explicit by passing the returned `sessionID`. This makes fresh execution the natural default and continuation an intentional choice.

Current OpenAI orchestration guidance recommends keeping the manager in control when specialists are bounded capabilities. The workflow owner therefore decides whether an assignment is new or continuing rather than letting specialist identity implicitly own session continuity.

Anthropic guidance distinguishes isolated/independent subagent work from stateful sequential work and separately notes that fresh-context verifier subagents improve independent checking. The resulting policy therefore requires freshness for new independent judgments while preserving continuity for the same specialist-owned workstream.

## Non-changes

- No new agent is added.
- `semantic-checkpoint.md` and `session-evaluator.md` are unchanged.
- Checkpoint trigger conditions and verdict semantics are unchanged.
- Existing `proceed` / `hold` / `unverified` lifecycle behavior from v30.34 is unchanged.
- No provider/model-specific routing is introduced.
