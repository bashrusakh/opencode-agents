# v31.15 beta — Audit access for governing skills

## Defect and scope

`session-evaluator` has to judge instruction compliance based on the governing contracts, but its configuration-folder read policy allowed root `AGENTS.md` and `agents/*.md` while denying installed `skills/*/SKILL.md`. In multiple inspected child sessions it therefore marked delegation/readiness rules unavailable and left material judgments unverified.

## Fix

Allow the `session-evaluator` to **read** the canonical installed `~/.config/opencode/skills/*/SKILL.md` paths after the existing config deny, preserving OpenCode V2 last-match precedence. This does not allow arbitrary config files, other skill content, secret files, modifications, shell execution, delegation, or unrelated skill invocation.

An existing static policy checker now guards that boundary, including retained config deny and role-wide deny. Runtime permissions should additionally be tested in the user's actual OpenCode installation; static guards cannot prove host policy overrides.

## Communication comparative audit

The accompanying release evidence compares 13 supplied session exports by role/model. It does not modify `AGENTS.md` communication semantics based solely on weak-model verbosity. Sol's substantive checkpoints, MiniMax's frequent tool-call narration, and DeepSeek's mixture of final-only and substantive progress are distinguished there.

Compare the distributable ZIP with v31.14 using `prior-release-preservation` and release gates. No other agents, skill contracts, or workflow procedures should change.
