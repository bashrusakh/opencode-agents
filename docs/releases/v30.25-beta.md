# OpenCode Agent Pack v30.25 beta

## Scope

Integration fix for the planning-role namespace. The package planning semantics are unchanged; the role ID changes so repository planning does not depend on overriding OpenCode's shipped `plan` agent.

## Why

Current OpenCode V2 ships a `plan` agent with an additional policy that denies normal project edits except OpenCode-managed plan files under `~/.opencode/plan`. The package used the same agent ID while intentionally allowing authorized durable planning artifacts under the target repository's `plans/` or `.opencode/plans/` paths. That name collision made effective write capability depend on built-in override/merge behavior.

## Changes

- `agents/plan.md` is renamed to `agents/project-planner.md`.
- Root routing and `code-orchestrator` handoffs now use `@project-planner` for architecture/sequencing and durable planning.
- The planning role keeps its existing narrow edit allowlist for `.opencode/plans/**/*.md` and `plans/**/*.md`; source/config/test implementation remains denied.
- Global and project installers back up and remove the obsolete package-owned `agents/plan.md` before copying the new agent set, preventing the old conflicting definition from surviving an upgrade.
- Historical release notes are not rewritten; references to `@plan` in old release notes describe the versions that actually shipped at that time.

## External compatibility basis

The current OpenCode V2 documentation describes `plan` as a shipped primary agent whose additional policy denies edits except OpenCode plan files, and documents that agent definitions/permission rules merge in configuration order. The package avoids relying on those override details by using a distinct custom role ID.
