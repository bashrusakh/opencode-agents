# v30.60 beta

## Changes

- Root delegation now distinguishes **fresh child identity** from **judgment-context isolation**. A fresh independent judgment receives authoritative target/state, requirements, constraints, and evidence needed for inspection, but is not seeded with prior verdicts, expected outcomes, parent conclusions, claimed-clean areas, or fix-history framing.
- `code-orchestrator` operationalizes the rule for fresh whole-change/final reviewer handoffs: exact target/Base+Candidate and authoritative acceptance/constraints go in; prior reviewer/OCR verdicts/findings, fix-delta framing, claimed-clean areas, and CI/test pass/fail conclusions stay in orchestrator state until post-review reconciliation.
- Targeted re-review remains valid and may receive the known finding/delta it is assigned to re-check, but its result remains explicitly partial/incremental and cannot satisfy a fresh whole-scope review or `Coverage: full PR` claim.
- `session-evaluator` now diagnoses context contamination and partial-to-full verdict laundering in independent-judgment handoffs.
- ST-32 adds an incident-independent regression for fresh whole-scope review anchoring while preserving the targeted re-review mode. Static policy regressions require the root owner, orchestrator consumer, evaluator diagnostic, and eval case.
- `reviewer.md`, `open-code-review-delegate`, and managed OCR policy are unchanged from v30.59; mandatory deterministic delegate preflight remains in force.
- A generic release-identity guard now keeps the root pack version aligned with README header/footer and the current changelog heading; the stale README footer inherited from earlier betas is corrected.
