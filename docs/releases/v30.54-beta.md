# v30.54 beta

## Changes

- `code-orchestrator` now preserves a contemporaneous provenance receipt before dependent handoff when a material user response is carried by an interaction channel whose primary record will not be retrievable by downstream semantic roles. The receipt records the exact proposition/response/qualifiers and preserves evidence only; it does not create or broaden authority.
- `session-evidence` consumes such receipts only when the primary interaction is unavailable, prefers retrievable primary interaction, rejects later paraphrases such as `user decided X` as equivalent evidence, and keeps unresolved provenance `partial/unverified`.
- `reviewer` now checks relevant create/update/delete/restore/reconstruct compositions when a candidate reconstructs or reconciles shared state, including intentional-state versus accidental-absence distinctions where material.
- `reviewer` now requires reachability evidence for claimed fallback/recovery behavior through material earlier guards, transformations, and failure points; branch existence alone is not behavioral proof.
- The temporary semantic-transition suite expands from 21 to 25 scenarios. ST-22 and ST-23 regress the new reviewer obligations; ST-24 and ST-25 are eval-only probes of the already-existing evidence-fidelity and fix-level/convergence rules.
- Semantic replay trace metadata now records policy/runtime identity for reproducibility without adding version/SHA fields to user-visible Startup messages.

## Validation status

Static policy regressions pass. Four mutation probes independently remove the orchestrator receipt, session-evidence receipt-consumption, reviewer state-composition, and reviewer fallback-reachability guards; each mutation correctly makes the structural harness fail. Runtime semantic changes are limited to `code-orchestrator`, `reviewer`, and `session-evidence` plus the root version marker. Fresh isolated replay of the 25 semantic transition scenarios remains separate behavioral evidence and is not claimed by this release.
