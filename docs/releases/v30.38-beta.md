# v30.38 beta

## Purpose

Close the semantic-correspondence gap where an agent-originated proposition can acquire apparent user authority through bundling, option descriptions, paraphrase, repetition, or downstream handoffs, and where a permitted fallback can lose its qualification and replace a stronger established outcome without a demonstrated blocker.

## Runtime changes

### Root `AGENTS.md`

Section 2.2.1 now makes four relationships explicit:

- a user response authorizes only the material proposition actually presented for decision;
- independently choosable semantics embedded in descriptive text do not become authorized merely because the surrounding option was selected;
- semantic correspondence and qualifications must survive questions, summaries, plans, assignments, checkpoints, and handoffs;
- a weaker fallback cannot replace a viable stronger established outcome without an established blocker or separate authority accepting the reduction.

The rule remains claim-level and generic. It does not add a new workflow stage.

### `code-orchestrator`

The workflow owner must keep user questions and selectable answers aligned to one material decision, identify material semantic deltas before checkpoint/handoff, preserve qualifications, and avoid promoting an easier permitted fallback over a viable outcome-preserving path without the required premise or authority.

### `semantic-checkpoint`

The gate now compares each material candidate proposition with the strongest primary authority source, checks whether user authority has been expanded by question/option framing or downstream restatement, preserves conditional/fallback status, and blocks unjustified weakening of an established outcome.

### `session-evaluator`

The post-hoc auditor now traces semantic delta across the causal chain, compares claimed user authority with the actual user-visible decision, detects proposal-to-authority promotion and qualifier loss, and treats unauthorized authority expansion as an instruction violation when the governing rule is established.

## Boundedness

- No new agent, skill, command, tool, or mandatory stage.
- Existing checkpoint verdicts and fresh-session rules are unchanged.
- Existing provenance-lineage recovery from v30.37 remains unchanged.
- Role prompts contain only role-specific application rules; the canonical semantic rule remains in root §2.2.1.

## Regression invariants

The semantic audit for this release covers at least these generic relations:

1. a user answer cannot authorize a second independently choosable proposition merely because both were bundled in descriptive text;
2. necessary consequences may still flow without a redundant user confirmation;
3. paraphrase and repetition do not strengthen authority;
4. a conditional alternative remains conditional until its premise is established;
5. a permitted fallback is not automatically equivalent to the strongest accepted outcome;
6. a weaker outcome requires a blocker to the stronger authorized path or separate authority accepting the reduction;
7. a checkpoint must inspect semantic delta, not only the final candidate wording;
8. a post-hoc evaluator must trace the transformation chain back to primary authority rather than treating downstream attribution as proof;
9. ordinary implementation mechanics remain selectable without direct user authority when they do not change semantics;
10. cross-layer work remains allowed when necessary to preserve the established outcome.
