# v30.63 beta

## Changes

- `build` now treats an edit-capable handoff, plan, or `semantic-checkpoint` `proceed` verdict as authorization for an established semantic boundary rather than proof that a proposed mechanism is correct or a recipe to apply literally.
- Before semantic mutation, `build` establishes a compact implementation proof from repository evidence: required outcome, exact implementation constraints, narrowest existing owner/primitive, nearest preserved behavior/invariant, and material affected callers/states/input shapes.
- A suggested local patch shape remains a hypothesis unless authority truly requires that mechanism. If repository evidence shows the proposed local owner is incomplete/wrong, `build` must choose a better ordinary mechanic inside the same semantic boundary or stop for semantic/design expansion rather than silently widening scope.
- Before returning, `build` performs mandatory implementation self-review of the exact final diff/state and verifies the changed behavior plus nearest preserved/representative behavior. This self-review is implementation-local evidence, not a substitute for independent `@reviewer`/`@tester` judgment.
- Adds ST-36 for handoff/checkpoint-mechanism laundering into implementation proof and ST-37 for returning a focused-green candidate with an implementation-locally detectable preserved-behavior/integration defect.
- Root semantic policy, `code-orchestrator` semantics, and all skills remain unchanged apart from the version marker/documentation references.
