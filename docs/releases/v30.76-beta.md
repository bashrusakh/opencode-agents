# v30.76 beta — external technical evidence specialist

## Purpose

v30.76 adds `librarian` as a dedicated read-only owner for bounded external technical evidence. The role exists to establish what an external product/library/framework/API/protocol/tool/upstream source supports or documents for the relevant version/environment without absorbing repository discovery, implementation planning, code review, or local debugging.

## Runtime semantics

- `librarian` is `mode: all`: it can answer a direct bounded external-technical question or run as a delegated read-only specialist.
- Semantic ownership is intentionally disjoint:
  - `explore` = repository-local descriptive evidence / local present;
  - `librarian` = external technical evidence / external truth;
  - `project-planner` = prospective implementation structure / implementation future;
  - `general` = bounded fallback only when no more specific owner applies.
- Narrow manifest/lockfile/config reading is allowed only to identify a material external target/version; it does not grant repository-usage/call-path ownership.
- External best practice, maintainer preference, migration advice, or community convention remains evidence/recommendation rather than project authority. An upstream issue does not by itself establish the local root cause.

## Research method and result

The role binds the exact external target/version/applicability, chooses evidence by authority + exact-version applicability + directness, challenges the first plausible source for version/platform/freshness mismatch, reconciles conflicting sources without voting, and separates direct evidence from inference/community practice.

Result presentation is intentionally light: answer first; cite/link the strongest applicable provenance; surface conflicts, inference/community status, freshness/version limitations, or unresolved applicability only when material. Empty report sections are not required.

## Routing/topology

- root entry/delegation routing recognizes external technical docs/upstream/version evidence as `@librarian` work;
- `code-orchestrator -> librarian` is a direct delegation edge;
- `auditor -> librarian` is a direct delegation edge;
- `explore`, `general`, and `project-planner` do not directly delegate to Librarian; they return the adjacent evidence need to the caller/workflow owner.

Closed-world pack-owned relation inventory becomes **57 discovered / 57 classified**.

ST-65…ST-70 cover version binding, source conflict reconciliation, external-advice authority, Librarian/Explore/Planner ownership separation, caller handoff composition, and result-format semantics.
