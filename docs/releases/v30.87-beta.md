# v30.87 beta — fresh whole-review investigative-context isolation

## Purpose

v30.87 closes a semantic bypass found immediately after v30.86: removing an explicit parent-authored emphasis block was not sufficient because the same steering could be repackaged as methodological instructions inside an otherwise fresh whole-change reviewer assignment.

Fresh-review independence is now defined by the **function of information exposed to the reviewer**, not by its heading, formatting, or placement.

## Runtime semantic changes

### `code-orchestrator`

For a fresh whole-change/final review the caller now supplies only:

- exact target or Base/Candidate identity;
- authoritative task/acceptance propositions with recoverable provenance;
- genuinely binding implementation constraints when material;
- current publication artifacts whose claims are themselves part of the reviewed result.

The caller supplies **what must be true, why it is authoritative, and what exact state is being reviewed**. The reviewer owns where risk exists and how to investigate it.

Parent-derived investigative direction is prohibited regardless of presentation. This includes prior findings/fix history, suspected weak points, parent risk rankings, expected findings/conclusions, implementation surfaces selected because of prior rounds, investigation order, coverage decomposition, suggested probes/edge cases, test/stress recipes, claimed-clean areas, and test/CI framing.

If the user or adopted project policy explicitly requires a review method or emphasis, only that exact authoritative requirement is passed, with recoverable provenance and without parent-added investigative elaboration. A parent provenance label is a locator, not proof of authority and cannot strengthen a parent synthesis into a binding requirement.

Targeted/partial re-review remains allowed to receive the known finding and discriminating reproduction; its verdict remains partial/incremental.

### `reviewer`

Freshness is now explicitly a property of the information exposed to the reviewer, not the assignment label.

For fresh whole-change judgment, reviewer independently derives:

- affected surfaces;
- risk model;
- investigation strategy/order;
- discriminating probes;
- coverage method.

If parent-derived investigative direction has already been exposed, context is contaminated and reviewer stops before substantive fresh whole-change judgment and requests a clean assignment. It must not silently discount the steering and still claim independence.

Material parent-supplied provenance is not accepted as authority merely because it is labelled as such. When practical, reviewer recovers the actual authority source; otherwise it reports an authority gap.

## Eval / gate changes

- ST-107 is generalized from recent-fix emphasis to any parent-derived investigative direction;
- ST-108 preserves exact user/project-authoritative review requirements without allowing them to become the whole-review boundary;
- ST-109 requires reviewer to derive investigation method independently and blocks semantic bypass through rewording/repackaging;
- ST-110 blocks provenance laundering where a parent label is treated as authority;
- semantic transition inventory increases to 110 cases;
- the existing high-risk `code-orchestrator -> reviewer` edge is strengthened; topology remains unchanged.

## Preservation

No change to reviewer read-only permissions, targeted partial re-review, final Base-to-Candidate review semantics, managed review integration policy, publication lifecycle, implementation/debug/test/UI roles, or the v30.85 owner/control-plane model.

Fresh isolated behavioral replay remains a separate evidence class and is not claimed unless actually run.
