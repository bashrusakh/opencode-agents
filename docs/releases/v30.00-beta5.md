# v30.00-beta5 — deterministic document lifecycle cleanup

Status: **experimental beta**. Stable reference: **v28.42**.

## Goal

Remove documents that have no justified runtime lifecycle. A current runtime policy must either be resident in the root/owning role/command, or have a deterministic activation mechanism that injects it when required. A document that is merely available for a model to remember to read is not a correctness boundary.

## Removed documents

The following files were removed from the current bundle because their runtime obligations are already resident in the actual owning prompts, or because they were reference-only duplicates with no required consumer:

- `docs/auditor_agent.md`
- `docs/git_branch_provenance_policy.md`
- `docs/language_spec.md`
- `docs/ocr_review_policy.md`
- `docs/output_formatting_policy.md`
- `docs/persistent_planning_policy.md`
- `docs/pr_readiness.md`
- `docs/ui_component_policy.md`
- `docs/verification_strategy.md`

The language/framework skill-routing table from `language_spec.md` was moved into resident `AGENTS.md` §2.1.1 before deletion because skill choice is cross-role and must be available without a separate read.

## Remaining non-release docs

Only two procedural guides remain:

- `docs/ui_mcp_install_for_agent.md`
- `docs/uupm_install_for_agent.md`

They are intentionally large, rare setup procedures rather than normal runtime policies. Their explicit commands inject the applicable guide text into the command prompt **before model execution** using OpenCode command shell-output expansion:

- `/ui-mcp-setup` -> project `.opencode/docs/ui_mcp_install_for_agent.md`, else global `~/.config/opencode/docs/ui_mcp_install_for_agent.md`;
- `/ui-uupm-setup` -> project `.opencode/docs/uupm_install_for_agent.md`, else global `~/.config/opencode/docs/uupm_install_for_agent.md`.

If neither copy exists, the injected command output is a blocker and the role must stop rather than reconstruct the procedure from memory.

## Package invariant

For every non-release `docs/*.md` file:

1. identify its consumer;
2. identify the trigger that makes the document applicable;
3. establish that the content is deterministically supplied when that trigger runs;
4. establish why the content belongs outside the resident root/role/command contract.

A document with no valid answer is removed rather than retained as a passive reference.

## Preserved behavior

Beta4's semantic-dedup corrections remain intact. This release does not intentionally change approval gates, claim authority/semantic correspondence, Startup/state identity, role/capability/delegation boundaries, mutation/right-level/regression/verification rules, PR provenance, Draft/Candidate/Ready lifecycle, or agent frontmatter/model neutrality.
