# v30.80 — semantic-state typing, discovery falsification, installer ownership, and licensing

## Purpose

v30.80 combines four independently motivated fixes over v30.79:

1. correct a planning-owner/reference defect between root §2.3, `project-planner`, and `persistent-planning`;
2. separate three semantic axes that previously reused the literal `unverified`;
3. strengthen repository discovery against false absence/flow claims without expanding `explore` into a general audit role;
4. make installer mutation ownership explicit and preserve project/user configuration by default.

The release also adds an MIT license for pack-authored material and retained third-party notices for bundled material whose upstream provenance/license is established.

## Runtime semantic changes

### Persistent planning composition

Root §2.3 remains the owner of persistent-planning activation and canonical-state policy. The `persistent-planning` skill owns the fallback durable representation/resume procedure. `project-planner` no longer attributes that layout to root.

If the project's existing canonical planning owner is outside the planner's permitted write paths, the planner reads it as authoritative state and returns the exact update need to the caller for an authorized writer. It does not create a parallel `plans/...` source of truth merely to stay inside its own write permissions.

### Typed semantic state

The checkpoint/evaluator vocabulary is now type-stable:

- checkpoint verdict: `proceed | hold | insufficient-context`;
- evidence status: `established | unverified | contradicted`;
- proposition relation: `preserved | refined | strengthened | weakened | substituted | indeterminate`.

`hold` and `insufficient-context` both block mutation, but their meanings remain distinct. `semantic-checkpoint` and `session-evaluator` now reference root-owned weaken/substitute semantics instead of restating the same state machine, while retaining their role-specific gate/diagnostic actions.

### Explore false-success defense

For material negative repository claims, `explore` now searches relevant naming/alias variants, references/callers, and applicable generated/config surfaces proportionately to requested depth. It distinguishes `not found within <searched scope>` from `does not exist`, and never turns `not searched` into `not found`.

Call/data/state-flow claims require an actual relation edge (caller/reference/consumer/transition) rather than naming or file adjacency alone.

### New-tooling runners

Root §4 now states explicitly that package runners such as `npx`/`bunx` do not bypass the existing new-tooling gate. `open-code-review` keeps its upstream install/upgrade commands but makes the command-not-found installation path explicitly approval-gated.

## Installer safety

Both installers now write ownership receipts and use them for future stale-file cleanup. Filename coincidence alone is never treated as package ownership.

- Project-owned `./AGENTS.md` is not overwritten. If it exists and no recognizable global pack root is present, project installation stops before mutation.
- An unknown existing global `~/.config/opencode/AGENTS.md` stops global installation before mutation unless replacement is explicitly authorized through `OPENCODE_AGENT_PACK_REPLACE_GLOBAL_AGENTS=1`.
- Every colliding managed destination is backed up before replacement.
- Ambiguous legacy command/doc/tool names such as `review.md`, `debug.md`, `verify.md`, and `plan.md` are preserved unless a prior receipt proves package ownership.
- The aggregate release gate now executes isolated installer behavioral selftests.
