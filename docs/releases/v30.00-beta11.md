# v30.00-beta11 — restore the stable v28.42 code-orchestrator

beta10 restored only the stable role-local routing map. Behavioral testing showed that this was insufficient: the surrounding beta9-deduplicated orchestrator still allowed the model to rationalize specialist repository tracing as bounded coordination work.

## Decision

`agents/code-orchestrator.md` is restored **byte-for-byte from v28.42**. This is intentionally not another local rewrite or compact re-expression. The stable role prompt is the behavioral baseline that already demonstrated the desired orchestration semantics.

The restored file brings back the complete local enforcement context as one unit:

- semantic leaf-role routing;
- current-target/ref/SHA identity and mutation-baseline handling;
- discovery cadence;
- fix-boundary and failed-hypothesis reset behavior;
- user-decision batching;
- reviewer and tester cadence;
- findings/invariant escalation;
- bugfix, existing-PR, bug-derived-issue, tests/docs, and release workflows;
- evidence freshness;
- planning/publication sequencing;
- final reporting.

## Why the full file is restored

The #3512 regression demonstrated that textual equivalence in root is not sufficient when the model needs role-local enforcement at decision time. beta10 had the correct stable routing list and discovery cadence, yet the shortened surrounding prompt still produced the wrong decision. The safe experiment is therefore the exact stable role prompt, not another invented exception.

## Regression scenario

For an issue-analysis request that explicitly requires repository code/tests/call-site/data-flow/ownership tracing:

- establish the authoritative target/ref/SHA when the claim is target-bound;
- route the bounded repository discovery/architecture-tracing assignment to `@explore`, even when issue/bot context already names candidate files;
- treat issue, maintainer, bot, and proposed-fix statements as claims to reconcile, not repository evidence;
- keep `@debugger` for requested root-cause implementation, not read-only analysis;
- invoke `@tester` only when independent executable/reproduction evidence is actually required;
- keep final claim authority/reconciliation with the orchestrator.

## Unchanged beta10 surfaces

Root `AGENTS.md`, the other 14 agents, all skill source content, installers, zero custom commands, zero snippets, setup documentation, and runtime discovery surfaces are unchanged from beta10.
