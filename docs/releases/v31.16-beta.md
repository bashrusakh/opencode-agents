# v31.16 beta — Evidence-first final review cadence

## Scope and reason

A workflow owner could run expensive final whole-change `@reviewer` concurrently with independent verification (tester/browser smoke/cleanup) still able to invalidate the current candidate. If those checks found a defect, the resulting code changes could stale an expensive review. Existing stabilization and PR Candidate HEAD requirements did not explicitly govern this cross-specialist ordering.

## Narrow fix

The existing `skills/delegation-control/SKILL.md` → **Evidence reuse and review cadence** now defaults to finishing candidate-invalidating implementation-local and independent verification, correcting findings, and stabilizing the intended candidate before final whole-change review. Independent verification tasks can run concurrently when independent; expensive final reviewer concurrency merely to shorten wall-clock time is discouraged in favor of the user's cost/latency priorities.

Do not block pre-publication review on remote CI that cannot run until a Draft push: classify unavailable/deferred checks accurately. Early bounded targeted review for a material question remains available and stays explicitly partial. A different ordering requires a concrete reason with its tradeoff visible; the owner retains stage-selection responsibility.

## Preservation

No role bodies, `pr-readiness`, `change-contract`, `AGENTS.md` operational semantics, permissions, tool availability, or installer policies change. The only runtime semantic change is the existing delegation-control skill. Prior release comparison and fresh release gates remain required.
