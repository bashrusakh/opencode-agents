# v30.86 beta — fresh whole-review context isolation

## Purpose

v30.86 fixes an accepted but previously unapplied review-handoff issue: a nominally fresh whole-PR reviewer could receive a parent-authored `Focus` section derived from the most recent findings/fixes and then use that focus as its practical review plan. The effective diff could still be structurally covered, but the independent risk model was anchored by the workflow owner's recent history.

The release keeps the v30.85 accountable-owner control plane intact. It changes only the fresh-review boundary between `code-orchestrator` and `reviewer`.

## Runtime semantic changes

### `code-orchestrator`

For fresh whole-change/final review, the handoff now contains only:

- exact target or Base/Candidate identity;
- authoritative task-contract propositions with provenance;
- separately established implementation constraints when material;
- current inspectable artifacts needed for judgment.

The parent must not add a `Focus`, `Risks`, `Recent fixes`, expected-check checklist, or test/reproduction recipe derived from prior review/fix/CI history. If a highlighted concern is actually authoritative required behavior, only the underlying contract proposition is passed. If the user or project policy explicitly requested emphasis, it may be preserved with provenance as additive/non-exhaustive emphasis.

Prior findings, targeted re-review results, fix-delta history, claimed-clean areas, test/CI conclusions, and expected verdicts remain in parent state and are reconciled only after the fresh reviewer returns.

### `reviewer`

Fresh whole-change review now has an explicit self-defense boundary. The reviewer derives its review surface/risk model from the authoritative contract plus the actual Candidate/effective diff. Caller-authored recent-fix focus/checklists are not authority or a review oracle.

If a nominally fresh assignment already exposes prohibited judgmental history, the fresh context is considered contaminated; reviewer stops before substantive whole-change judgment and requests a clean fresh assignment instead of pretending the seen history can be mentally ignored.

User/project-policy emphasis remains supported as additive and non-exhaustive. Targeted/partial re-review remains allowed to receive the known finding and discriminating reproduction, with a partial/incremental verdict only.

## Why no parent Focus is needed after a fix

The existing `pr-readiness` contract already requires that `changes required` be followed by a corrected Candidate HEAD and a repeated final whole-PR `Base SHA -> Candidate HEAD` review before publication. It does **not** require a separate targeted re-review after every fix.

Therefore the final whole-PR review itself is the independent check of the corrected state. Seeding the just-fixed finding into that review does not add required coverage; it biases the independent judgment. A targeted re-review may still be used when useful, but its history is withheld from the later fresh whole-PR reviewer.

## Eval / gate changes

- adds a dedicated high-risk `code-orchestrator -> reviewer` handoff profile; high-risk profiles increase 16 -> 17 while the relation inventory remains 59/59;
- strengthens ST-32 judgment-context isolation;
- adds ST-107: parent-authored recent-fix focus must not steer fresh whole-change review;
- adds ST-108: explicit user/project review emphasis is preserved as additive/non-exhaustive;
- static/protocol guards require reviewer to stop on contaminated fresh context rather than issue a nominal independent verdict.

## Preservation

No change to targeted partial review, final Base→Candidate coverage requirements, managed OCR policy, reviewer read-only permissions, `pr-readiness`, or v30.85 owner/controller semantics.

Fresh isolated behavioral replay is not claimed unless actually run.
