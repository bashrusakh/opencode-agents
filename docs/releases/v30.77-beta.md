# v30.77 beta — delegated-specialist README/topology consistency

## Purpose

v30.77 fixes a documentation drift exposed after adding `librarian`: the README's `## Delegated specialists` table listed only `mode: subagent` roles even though the runtime topology also delegates several `mode: all` roles. That made the user-facing delegation inventory incomplete while the underlying role contracts and handoff topology were already correct.

## Documentation semantics

`## Delegated specialists` now means what its heading says: every role that is actually the target of a classified `delegation` or `conditional_delegate` edge is represented, regardless of whether its mode is `subagent` or `all`.

The delegated `mode: all` roles are:

- `build`;
- `project-planner`;
- `librarian`;
- `ui-orchestrator`.

They remain valid direct/top-level owners for their narrower tasks; being listed as delegated specialists does not change their role contracts or routing authority.

## Generic consistency guard

`evals/static-policy-regressions.py` now derives the expected delegated-specialist set from the closed-world `EDGE_CLASSIFICATION` inventory and compares it exactly with the README table. Missing delegation targets and stale README entries both fail release. The guard is topology-derived rather than hard-coded to the current role list.

## Runtime preservation

Runtime semantics are unchanged from v30.76:

- 18 agents;
- 22 skills;
- 57 discovered / 57 classified pack-owned role relations;
- ST-01…ST-70 retained;
- behavioral replay remains pending and is not implied by static/contract/package PASS.
