# v30.62 beta

## Changes

- `code-orchestrator` now routes a concrete product-code defect established by valid independent reviewer/tester/CI/reproduction evidence after an implementation package is returned according to the current action: confirmed bug/failure correction belongs to `@debugger`, not another ordinary `@build` iteration.
- The rule preserves build-local self-correction before package return, keeps mechanical non-bug/tests/docs corrections with their normal owner, and reuses existing root reset/escalation semantics when a debugger correction is materially rejected or repeated findings converge on one invariant/state/protocol model.
- `build` now explicitly returns an incorrectly assigned post-return confirmed bugfix to the caller for debugger routing rather than absorbing it as normal implementation.
- Adds ST-35 plus owner-specific static guards. Root routing semantics are unchanged apart from the version marker.

## Validation status

Static/mutation/package checks are recorded in `opencode_v30_62_beta_validation.md`. Fresh isolated behavioral replay of ST-01…ST-35 remains separate evidence and is not claimed by this release.
