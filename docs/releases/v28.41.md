# v28.41 — Alibaba OCR managed-review sync

v28.41 synchronizes the packaged managed `open-code-review` skill with current Alibaba OCR behavior while keeping the package-specific reviewer/delegation architecture intact.

## Managed-review common path

The normal OCR skill now runs the requested `ocr review` directly instead of spending an initial tool call on `command -v ocr`, `which ocr`, or `ocr --version`. Installation handling is entered only when the review invocation actually fails because the command is unavailable.

This change applies only to managed `ocr review`. Delegate-mode capability probing remains intentional because the host integration must detect whether the installed CLI exposes delegation and JSON-format support before choosing the compatible deterministic preflight path.

## Token-budget semantics

The `--max-tokens-budget` description now matches current OCR behavior:

- aggregate input + output budget is checked before every LLM round, not only between groups;
- once exhausted, no new review groups are dispatched;
- an already-running over-budget group may receive one bounded final round to submit pending findings;
- work that cannot continue is reported as `failed(budget)`;
- partial findings remain publishable.

The host reviewer still treats OCR output as evidence rather than authoritative scope or verdict.

## `--max-tools` semantics

The packaged skill now records the current review-template behavior: template default is `100`; values `1`-`49` are normalized to `50`; and the resolved CLI override only applies when it is greater than the template default. The flag therefore raises the effective limit but does not lower it.

## Attribution

The normal OCR skill metadata now uses `alibaba / package integration`, matching the fact that the bundle extends the upstream skill with package-specific session, target, validation, mutation-boundary, and integration guidance.

## Unchanged

- `open-code-review-delegate` capability probing and deterministic `preview` + `rule` workflow
- authoritative changed-set reconciliation using `(path, status)` identity
- host `@reviewer` ownership of scope, coverage, semantic judgment, and final verdict
- review-only mutation boundary
- managed OCR as optional/required second-model evidence according to existing policy
