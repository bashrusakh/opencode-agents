# OpenCode Agent Pack v30.65 beta

## Purpose

v30.65 fixes cross-role mutation-handoff contamination exposed by re-reading the full historical implementation/review trace analysis. v30.64 strengthened builder self-falsification, but upstream read-only roles could still make a non-authoritative mechanism look pre-approved before it reached the mutation role.

## Diagnosis

The runtime contracts had an internal asymmetry:

- `build` correctly said that a handoff or `semantic-checkpoint proceed` verdict is not an implementation recipe or correctness proof;
- `code-orchestrator` said ordinary technical mechanics remain implementation-owned;
- but `semantic-checkpoint` still evaluated proposed-mechanism adequacy and reported whether the candidate could be passed unchanged to an edit-capable specialist;
- correction handoffs could still preserve reviewer/tester remediation shape too literally even though the finding itself was only evidence of a defect;
- UI plan/audit artifacts had the same generic risk of being forwarded as blanket implementation authority.

That combination can anchor a weaker implementation model on an upstream patch shape even when the role contract later tells it to reason independently.

## Runtime changes

- Root task-semantic authority now makes mechanism selection role/authority-owned: upstream roles may propose non-binding hypotheses, but do not bind downstream implementation unless authority actually requires the mechanism.
- `semantic-checkpoint` now gates only the semantic mutation boundary. It may reject a mechanism that embeds an unsupported semantic assumption, but `proceed` does not certify technical/design adequacy, approve a patch shape, or recommend passing the candidate/checkpoint report unchanged.
- `code-orchestrator` reconstructs edit-capable assignments from established outcomes, exact implementation constraints, target/evidence state, and checked bounds. Non-required mechanism/remediation proposals are omitted by default; technically necessary context is explicitly non-binding.
- Confirmed defects routed to `@debugger` carry the defect proposition, governing expected behavior/invariant, reproduction/evidence, affected boundary, and exact state. Reviewer/tester remediation suggestions do not become the assigned fix unless separately established as implementation constraints.
- `debugger` treats proposed remediation/patch shapes as hypotheses and diagnoses from the governing behavior and evidence.
- `session-evaluator` audits mutation-handoff recipe laundering explicitly.
- `ui-orchestrator` / `ui-implementer` apply the same proposition-scoped rule to plan/audit → implementation handoffs.

`build.md`, `reviewer.md`, and `tester.md` are intentionally unchanged from v30.64: v30.65 fixes the upstream/downstream handoff boundary rather than adding more builder policy.

## Regression coverage

The semantic transition suite expands from 43 to 46 scenarios:

- ST-44 — semantic checkpoint authorization must not certify or forward an implementation recipe;
- ST-45 — a confirmed finding must become a debugger defect contract, not a reviewer patch recipe;
- ST-46 — a plan or audit must not become blanket mutation authority.

Static guards cover root mechanism ownership, checkpoint boundary semantics, orchestrator mutation-handoff reconstruction, debugger anti-anchoring, evaluator diagnostics, and UI plan/audit handoffs.

Fresh isolated behavioral replay remains separate from static/package validation and is not claimed unless actually run.
