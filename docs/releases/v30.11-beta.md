# v30.11 beta

Semantic ownership clarification built on v30.10 beta.

## Why

The v30.10 workflow/execution ambiguity split was correct, but two phrases still allowed a parent orchestrator to absorb part of a leaf role's path-finding work: broad `finding the relevant path -> @explore` routing and a pre-handoff fix-boundary proof requirement.

## Changes

- Defines the orchestration boundary as **goal/envelope/stage owner** versus the leaf's **execution path**.
- Routes `@explore` for an explicit discovery/mapping deliverable or when repository/architecture mapping is needed to bound workflow scope safely; unknown exact implementation details alone are not a discovery stage.
- For non-trivial fixes, the orchestrator establishes the semantic acceptance condition plus preserved behavior/invariant. The assigned implementation/debugging role performs root-cause tracing and chooses/proves the narrowest existing ownership boundary under root §7.2.
- If that leaf discovers that correctness requires materially broader scope, architecture/product direction, or authority, it escalates instead of silently widening the envelope.

## Non-goals

This does not turn routing into a fixed pipeline or remove model judgment. Materiality, scope breadth, risk, meaningful verification/review boundaries, and escalation remain semantic decisions. Role capabilities, permissions, gates, topology, installers, and skills are unchanged.
