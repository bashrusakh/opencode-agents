# v30.10 beta

Semantic handoff clarification release built on v30.9 beta.

## Why

Testing showed that phrases such as `already-understood` and `remove ambiguity` could be read as requiring an orchestrator to discover exact implementation details before delegating a focused leaf stage. That interpretation wastes parent context and can blur role ownership.

## Changes

- Defines **workflow-level ambiguity** separately from **execution-local ambiguity**.
- Requires the workflow owner to resolve the former, while exact files/symbols/call sites/nearby implementation mechanics normally remain with the selected specialist inside its bounded envelope.
- Clarifies direct focused routing to `@build` / `@ui-implementer` when outcome and behavioral/product direction are bounded; unknown exact implementation details alone do not require parent discovery or an intermediate `@explore`.
- Applies the same wording discipline to `build`, `plan`, `ui-implementer`, `ui-orchestrator`, `ui-planner`, focused-UI target semantics, and exploration-depth language.

## Non-goals

This does **not** turn semantic routing into a fixed pipeline. Materiality, risk, meaningful boundaries, stage economy, escalation, and whether a separate discovery/review/test stage adds value remain judgment calls. Role capabilities, permissions, gates, topology, installers, and skills are unchanged.
