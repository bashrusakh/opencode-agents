# v30.40 beta

## Purpose

Apply the Semantic Design Manual to the shared root instruction itself: keep truly global semantic invariants in permanent context, move conditional integration/procedure detail behind skills, and preserve the v30.38/v30.39 authority semantics unchanged.

## Root changes

### Memory / GrayMatter

Root no longer requires memory search on every task merely because GrayMatter is installed. Recall is triggered only when prior unfinished work, preferences, decisions, conventions, workarounds, or task history can materially affect the next action. Detailed identity/tool/storage mechanics move to `graymatter-memory`. Memory remains recall evidence, never repository authority.

### Skill activation

Root no longer duplicates the language/framework specialist inventory. It selects from the actual project/runtime-exposed skill catalog and keeps only workflow/policy skills that root itself conditionally activates.

### Persistent planning

Root keeps the semantic trigger and durable-state requirements: use persistent planning only when continuity genuinely needs it, preserve one reconstructable authoritative task state, and do not create planning machinery for short/read-only work. The default `plans/<plan>/...` representation and work-package procedure move to `persistent-planning`, subordinate to project-owned planning conventions.

### Temporary semantic-eval harness

`session-evaluator` remains intentionally enabled as beta instrumentation for finding instruction/action errors, but it is no longer invoked after every non-trivial intermediate run. It runs once only when `code-orchestrator` reaches a terminal successful outcome about to be reported:

1. the normalized session goal is satisfied; or
2. an owned PR candidate reaches final PR-ready/readiness state.

It does not run for intermediate work packages, routine iterations, pauses, blocked/failed work, or an unsatisfied goal. It remains post-hoc diagnostic evidence and never reopens or gates completed work. The root explicitly marks this policy temporary and removable when semantic-eval collection is no longer actively used.

### Mutation mechanism

Root keeps only the shared invariant: choose a narrow reliable mutation mechanism, constrain bulk/programmatic target sets, use transforms only for understood mechanical changes, inspect the resulting diff/state, and never let tool choice widen scope. Editor-vs-script preference is no longer permanent root procedure.

## New conditional skills

- `graymatter-memory` — relevant recall, checkpoint continuation, durable-memory hygiene, and GrayMatter tool mechanics.
- `persistent-planning` — project-first durable planning, default pack layout when no project convention exists, reconstructable state, and a minimal work-package cycle.

## Preserved semantics

No change is intended to:

- claim-level user/project authority;
- semantic correspondence, qualifiers, and fallback status;
- authority-vs-evidence separation;
- role/capability boundaries;
- human gates;
- conditional delegation and session continuity;
- state-bound verification;
- v30.39 communication cadence;
- v30.39 removal of the v30.37 provenance-lineage workaround.
