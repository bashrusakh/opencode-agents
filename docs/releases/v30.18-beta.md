# OpenCode Agent Pack v30.18 beta

## Scope

Semantic framing / production-quality correction built directly on v30.17 beta.

## Runtime changes

- Treats the first plausible non-trivial framing/fix level as a hypothesis and requires a materially different counter-framing only when it could change the outcome.
- Separates leaf technical implementation freedom from workflow-owner authority over new product/domain semantics, identities, ownership/source-of-truth rules, and destructive boundaries.
- Extends right-level discipline from bug corrections to all non-trivial implementation and defines production-grade behavior operationally without turning it into speculative “enterprise” architecture.
- Makes unexpected selectors/identities/persistence/coordination/guards a signal to re-check framing before design expansion.
- Adds reviewer coverage for technically coherent but unauthorized semantic scope creep.

## Non-changes

- No agent topology, `mode`, permission, routing-table, installer, or skill-inventory change.
- No provider/model-specific `model:` overrides are added.
- `@plan` remains conditional for genuine unresolved architecture/sequencing; it is not inserted as a mandatory stage.

## Prompt-design reference

The semantic/prompt-policy changes were reviewed against OpenAI's current-model prompting guidance:

<https://developers.openai.com/api/docs/guides/latest-model>

The guide's emphasis on lean prompts, clear scope/autonomy, explicit success/evidence criteria, and avoiding duplicated/conflicting instructions informed this release. The pack remains provider/model-agnostic; the reference is design input, not a model pin.

## Regression target

A #63-like underspecified destructive feature should force the workflow owner to resolve “what entity/action does Delete mean?” before a leaf silently introduces a new physical-copy/product contract. A trivial local bug with a clear semantic boundary should still proceed without planning ceremony.
