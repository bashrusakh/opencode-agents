# v31.10 beta — Reviewer performance-proof fidelity and semantic audit

The reviewer now matches material performance claims to evidence that measures or soundly establishes the **claimed effect**. A local reduction in work does not, by itself, prove a user-visible/end-to-end performance gain. Performance regression findings still require material evidence; no ritual benchmark, invented performance budget, or mandatory measurement for a merely structural claim has been introduced. An acceptance-critical impact claim lacking discriminating proof must remain an explicit evidence gap, not be treated as passed.

The affected-behavior review entrypoint is now defined for both code/diff targets (authoritative Base-to-Candidate) and plan/result targets without an applicable diff (established acceptance and proposed/observed behavior). Its material dependency boundary and preserved-invariant logic are unchanged.

Two redundant reviewer reminders were removed: a second `no benchmark by ritual` from the critical-resource specialization, and a generic evidence-limitation sentence already covered by authority/evidence, risk-specific handling and result. No owner relocation, extra mandatory review stage, new `ST-*`, or role/skill topology change.

See the separately distributed `opencode_v31_10_reviewer_semantic_audit.md` for line-by-line ownership, duplicates, risk, semantic behavior matrix, and proof limitations. Gate PASS checks semantic/static pack consistency; independent runtime replay is not claimed.
