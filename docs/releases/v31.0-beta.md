# v31.0 beta

Behavioral orchestration hardening over v30.100, motivated by a clean v30.100 owned-PR workflow that exposed both missing and excessive whole-review transitions.

- `pr-readiness` now owns an explicit **Correction / stabilization** state after final whole-review `changes required`. A bounded correction package does not become Candidate HEAD merely because it is committed, locally green, spot-checked, or targeted-re-reviewed. The correction set must be closed as a combined state before one new Candidate HEAD enters final whole-PR review.
- A materially related blocker from the next final whole-review reopens stabilization and requires owner reassessment before another Candidate promotion; final review must not become an iterative discovery loop after each local fix.
- Ready authorization and Ready evidence remain distinct. A requested action sequence such as push/publish -> CI -> Ready does not implicitly waive a missing whole-review prerequisite; an override must be explicit about proceeding without the missing prerequisite.
- The universal capability boundary now makes action ceilings apply to all task-relevant state. `delegation-control` specializes this into a delegated-state boundary: out-of-bound target/resource ownership/topology or relocation transitions must return to the caller before mutation. `resource-lifecycle` reconciles validly authorized resources but does not authorize their creation or relocation.
- Release gates add end-to-end/mutation checks for the three observed failure classes and semantic traces ST-142..ST-144. The resource-drift regression may use a concrete worktree-like mutation as a test fixture, but the normative rule remains provider/resource agnostic.

Permissions/frontmatter and bundled vendor skill subtrees are intentionally unchanged. Fresh isolated behavioral replay of ST-142..ST-144 is not claimed by this beta release.
