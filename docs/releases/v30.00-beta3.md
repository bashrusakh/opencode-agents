# v30.00-beta3 — root semantic deduplication

Status: **experimental beta**. Stable reference: **v28.42**.

## Scope

This beta deliberately targets one architectural problem: semantic duplication between the always-resident root `AGENTS.md` and role prompts. It is rebuilt from clean v28.42, not from beta2.

Most role contracts stay byte-identical. A few owning roles receive only the small pieces that were unique to the removed root workflow text (UI policy location/quick redesign, tests/docs-only edit semantics, bug-derived issue drafting details, and release-source handling). Agent frontmatter, modes, permissions, provider/model behavior, commands, skills, approval gates, role/capability boundaries, verification cadence, and PR provenance/readiness mechanics are unchanged.

## Removed from root

### OCR workflow mechanics

The former root `§5.2` duplicated `agents/reviewer.md`: exact target binding, authoritative changed-set accounting, delegate preview/rule reconciliation, native fallback, managed OCR escalation, external-sharing boundary, optional managed-OCR failure behavior, and review-only no-fix behavior. Those mandatory review semantics remain resident whenever `@reviewer` runs, so beta3 removes the second root copy rather than adding another policy read.

### Role-specific workflow pipelines

The former root `§6.1–6.9` duplicated the selected role contracts:

- UI intent/stages/component-source coordination -> UI role prompts;
- multi-step bugfix, complexity iteration, tests/docs coordination, existing-PR follow-up, bug-derived issue, release prep -> `agents/code-orchestrator.md` and its implementation specialists;
- project audit -> `agents/auditor.md`;
- runtime/CI/deployment work -> `agents/devops.md`.

Root §6 is now only an architectural boundary: root routes and constrains; the selected role executes its own workflow. Any root-only residue required to make a role self-contained was moved into that role rather than left behind or replaced with a new generic lazy-loader.

## Explicitly unchanged

The following remain resident and are intentionally not part of this refactor:

- philosophy/source-of-truth/state identity and GrayMatter;
- behavioral contract and claim authority/semantic correspondence;
- persistent planning activation;
- Startup/Update;
- role/capability boundaries;
- request normalization;
- approval gates;
- delegation/workflow ownership and stage economy;
- before-edit identity/provenance checks;
- mutation mechanism, right-level fixes, regression guard;
- verification cadence/evidence freshness;
- Git/PR provenance plus Draft/Candidate/Ready gates;
- output/final-report rules.

## Cross-reference repairs

Two references inside the unchanged PR-readiness lifecycle pointed to deleted workflow-section numbers. They now point semantically to the active reviewer contract and applicable orchestration/planning contract. The gate conditions themselves are unchanged.

## Evaluation

Compare v30.00-beta3 directly against stable v28.42. The primary regression questions are whether routing still selects the same roles, whether review/OCR behavior remains complete without a separate policy-file read, and whether any behavior formerly supplied only by root §6 was actually missing from its owning role.

## Intentionally retained root/role overlap

A post-refactor semantic-similarity audit still shows overlap around PR readiness/provenance, persistent-planning activation, claim authority/semantic correspondence, delegation/stage economy, right-level fixes, verification/evidence freshness, and final reporting. This is intentional: those are cross-role invariants or gates that must be known before/around specialist execution, not role-private workflow mechanics. Beta3 does not optimize them further.
