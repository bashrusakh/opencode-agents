# v30.91 beta — semantic ownership as a release gate

## Summary

v30.91 closes a validation blind spot exposed by the v30.90 root/orchestrator deduplication pass. The design manual already required one canonical owner across the root→role→skill graph, but the release suite mainly proved that required semantics were present and that known guards survived. One edge audit had even required the orchestrator to repeat root-owned handoff fields.

The release now treats **semantic ownership** as a separate architectural evidence class. Material shared contracts are declared in `evals/semantic-ownership-spec.json` as:

`canonical owner → reference / consume / specialize consumer`.

A consumer becoming a second definition is a release finding even when the duplicate is consistent with the owner and current behavior remains correct.

## Runtime semantics

No new runtime workflow stage or role is added. The runtime behavior from v30.90 is preserved.

The design/eval interpretation is strengthened:

- role executability is **inherited shared contract + role-local method**;
- a consumer does not need to repeat generic root/skill policy to remain executable;
- legitimate role-local specialization remains allowed when the shared owner is still explicit;
- standing shared policy duplication is independently invalid because it creates context cost, owner ambiguity, and future drift risk.

## Evaluation changes

- adds `evals/semantic-ownership-spec.json`;
- adds `evals/semantic-ownership-audit.py`;
- adds `evals/semantic-ownership-selftest.py`;
- `run-release-gates.py` runs the selftest and full ownership audit on every release candidate;
- the initial manifest covers nine material shared capabilities spanning root, `code-orchestrator`, `reviewer`, `pr-readiness`, and the temporary session-evaluator integration;
- adds ST-120: a behaviorally consistent paraphrased duplicate in a consumer must still fail semantic ownership.

The synthetic selftest includes a paraphrased generic handoff schema rather than copying an old forbidden literal, so the gate is not only a historical-string blacklist.

## Evidence boundary

Static ownership, contract/protocol, handoff, installer, and mutation evidence remain distinct from behavioral model replay. ST-120 is structurally represented and its ownership gate is selftested, but no fresh isolated model replay is claimed by this release.
