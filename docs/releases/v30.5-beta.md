# v30.5 beta — complete skill inventory and policy-residency audit

v30.5 beta is a policy-linkage correction on top of v30.4 beta.

## Changes

- Root §2.1.1 now lists the complete bundled skill inventory.
- Skills are grouped into specialist/advisory skills and workflow/policy skills.
- All roles explicitly inherit the root skill catalog through the existing shared-root contract; role files do not duplicate the global inventory.
- A triggered workflow/policy skill must be loaded/read before relying on it for that stage. Skills remain procedural/advisory and cannot widen role authority, scope, gates, or project rules.
- `git-provenance` is now an explicit load for claims about current upstream/default/base state.
- Owned-PR follow-up/publication/readiness explicitly loads both `git-provenance` and `pr-readiness`.
- Entry routing and delegation routing are again listed separately in compact form, preserving frontmatter execution topology.
- `build` no longer points to removed root §8.1; it points to the current `git-provenance` mutation-baseline policy.
- `ui-orchestrator` no longer points to removed root §8.2; it points to root §8 plus the applicable `git-provenance` / `pr-readiness` policy skills.

## Validation focus

The release is validated for skill inventory completeness, policy activation coverage, root inheritance across every role, role/skill reference integrity, execution-topology routing, stale section references, installer residency, policy duplication, fallback/plan regressions, and the package's prohibited orchestration-pattern invariant.
