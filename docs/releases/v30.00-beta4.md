# v30.00-beta4 — corrected semantic dedup + policy ownership audit

Status: **experimental beta**. Stable reference: **v28.42**.

## Correction over beta3

A fourth ownership test was added to the root/role dedup audit: **when must this rule be known?** A rule that is required before role selection or across multiple independent roles remains resident in root; a rule used only after routing belongs to its owning role.

That test found and corrected five beta3 gaps:

1. generic multi-step coding workflows again route to `@code-orchestrator` from root;
2. orchestrator escalation again recognizes effective-diff expansion across interacting layers/consumers caused by an incomplete behavioral model;
3. reviewer evidence that the architecture/invariant model itself is incomplete is again an escalation signal;
4. file count/diff size alone is explicitly not an escalation signal;
5. `@ui-planner` now contains the compact component-source order it needs without relying on another document.

## Protected root contract

The following remain stable-owned and are not part of the role-dedup refactor: approval gates, claim authority/semantic correspondence, Startup, state identity, capability/delegation boundaries, pre-edit provenance/mutation baseline, mutation mechanism, right-level fixes, regression guard, verification/evidence freshness, PR branch provenance, Draft/Candidate/Ready gates, and output/final-claim honesty.

PR provenance is intentionally root-owned because it coordinates workflow owners, mutation roles, reviewer evidence and publication/Ready state; it is not delegated to one agent.

## Docs policy audit

The old policy documents were audited for actual runtime consumers and duplication. The result is intentionally simple: **no correctness-critical runtime behavior depends on reading these files**:

- `git_branch_provenance_policy.md` -> reference map to root §7.1/§8.1/§8.2 + orchestrator;
- `ocr_review_policy.md` -> reference map to root gates/state + `@reviewer` + OCR skills;
- `output_formatting_policy.md` -> reference map to root §9/§10 + role result contracts;
- `persistent_planning_policy.md` -> reference map to root §2.3 + `@plan` + orchestrator/commands;
- `pr_readiness.md` -> reference map to root §8.1/§8.2 + orchestrator/reviewer;
- `ui_component_policy.md` -> reference map to self-contained UI role prompts;
- `verification_strategy.md` -> reference map to root §5.1/§7.4 + `@tester` + implementation roles.

Their historical filenames are retained for link compatibility, but each now declares itself documentation-only and not a mandatory runtime policy load. This removes the beta2 failure mode where correctness depended on the model voluntarily reading another file.

The only intentional on-demand docs loads left in commands are `ui_mcp_install_for_agent.md` and `uupm_install_for_agent.md`. Those are procedural setup guides for explicit setup commands, not normal workflow policies; normal UI roles do not depend on them.

## Validation model

Beta4 is validated with four rule-residency checks:

1. exact-diff of protected stable sections;
2. semantic map from every removed rule family to its owning runtime contract;
3. reverse search for stable root obligations with no remaining runtime owner;
4. ownership timing: whether a rule must be resident before role selection/cross-role coordination or belongs only after routing.

The docs audit additionally verifies that reference-only policy filenames have zero runtime references from `AGENTS.md`, agents, commands and snippets.

- protected root §§0–4, §7 + §8.1, and §§9–10: byte-identical to v28.42;
- root §5 core: byte-identical after accounting for the single restored generic multi-step-coding routing line and removal of role-owned OCR detail;
- root §8.2: semantically byte-identical after normalizing the two stale section-reference repairs introduced by the dedup;
- removed-rule semantic coverage map: PASS for OCR, UI, bugfix/escalation, tests/docs, existing PR, bug-derived issue, audit, DevOps, and release workflows;
- independent reverse scan of 71 substantive fragments removed from stable §5.2/§6 found no remaining ownerless obligation after the beta4 corrections;
