# OpenCode Agent Pack v30.21 beta

## Scope

Root-prompt wording and changelog hygiene release built on v30.20 beta.

## Changes

- Root §0 now tells the agent to infer intended outcome/scope from instructions, prior conversation, repository state, project guidance, and tool evidence, then carry authorized in-scope action requests through the intended outcome.
- The non-trivial framing check is explicitly internal and uses `framing/solution level` rather than bug-centric `framing/fix level` wording.
- Root §7.2 is renamed to `Right-level implementation boundary` so the same abstraction-level discipline is salient for feature implementation and bugfix work.
- Repeated gate, ambiguity, skill-authority, and delegation-fallback wording is consolidated toward the existing canonical sections.
- Root public-writing policy now states that changelog entries list actual changes; preservation/regression assurances belong in validation or release-audit material.
- `CHANGELOG.md` historical entries that only described unchanged behavior are removed or rewritten around the actual change.
- README installer-validation wording now names the actual legacy cleanup classes: `command/doc/snippet`.

## Prompt-design basis

This release cross-checks the root prompt against OpenAI's current model prompting guidance:

<https://developers.openai.com/api/docs/guides/latest-model>

Applied guidance:

- infer intent and task scope from instructions and prior context, then follow authorized work through;
- keep prompts lean and state each instruction once;
- make approval/autonomy boundaries explicit and centralized;
- state public-facing actions/results directly instead of padding them with what did not change;
- use clear, concrete wording rather than broad style labels;
- calibrate testing and delegation to the task rather than forcing a fixed ritual.

The pack remains model-agnostic; the external guide is a prompt-design reference, not a runtime model selection rule.
