# v30.79 beta — reviewer / managed-OCR coverage independence

## Purpose

v30.79 closes a reviewer integration gap exposed by a fresh whole-PR trace: managed OCR could be treated as if it had performed the host reviewer's work for the files OCR selected, while the host directly inspected only the filtered/excluded complement. The resulting `OCR-selected + host-only = full PR` arithmetic can produce a structurally plausible but semantically false host-coverage claim.

The fix is deliberately reviewer-owned. It does not make managed OCR mandatory, change its CLI procedure, duplicate tester work, or require a second serial review pass.

## Runtime behavior

For code-like review with managed OCR:

- the reviewer first binds the authoritative changed/effective-diff set as before;
- host structural review coverage is accounted independently across that set;
- an entry selected/completed/commented on by OCR is not marked host-reviewed by that fact;
- host review and managed OCR may run in parallel;
- material OCR findings are reconciled against code, task authority, preserved behavior, and host evidence;
- zero OCR comments do not establish correctness;
- a complete verdict requires the reviewer's own applicable coverage/judgment, while explicitly required OCR must also complete under its existing integration contract.

The result contract now separates:

- `Coverage: ...` — host structural review coverage;
- `Managed OCR coverage: ...` — OCR selected/completed/failed/waived scope;
- OCR finding reconciliation when material.

This prevents coverage laundering without forcing duplicate executable verification: reviewer still reuses fresh tester/CI evidence and runs only bounded spot-checks needed for review claims.

## Methodology

The Semantic Design Manual generalizes the trace into an owner/integration rule: when a role owns a judgment, auxiliary integration coverage remains separate evidence unless judgment responsibility was explicitly transferred. Coverage union is not owner coverage, and an auxiliary zero-finding pass is not owner completion proof.

## Contract/eval changes

- reviewer runtime contract gains managed-review independence and separate coverage-ledger semantics;
- reviewer-specific protocol audit rejects OCR+host complement coverage;
- contract selftest includes a good independent-ledger case and a bad `OCR selected N + host remainder = full` case;
- static reviewer guard requires the runtime semantics;
- ST-75 adds the incident-independent behavioral transition case.
