# v31.22 — model-aware exception-driven session diagnostics

## Purpose

Make post-hoc session evaluation actionable and readable without reducing audit depth, losing model-attribution accuracy, or turning diagnostics into task-completion gates.

## Contract changes

- `agents/session-evaluator.md`: attributes material findings to the actor/model/effort active at the decision, including cross-model continuations; avoids counting one root cause multiple times; replaces the ten-part positive/negative report template with concise exception-first findings while retaining the full internal audit method and strict evidence/provenance qualification.
- `skills/session-evaluation-control/SKILL.md`: caller must reconcile material evaluator findings in its final user-facing report; a clean audit gets at most one scope-qualified sentence; missing or incomplete diagnostics are disclosed; prior task-scoped findings known in the same workflow remain material for a session-wide summary. Completion/readiness remains independent and non-gated.
- Regression fixtures cover model handoff, exception-driven reporting, diagnostic consumption, and persistence of earlier findings through later clean task-scoped diagnostics. No new roles, automatic re-audits, acceptance gates, tooling, or persistent artifacts.

## Validation boundary

Static/structural contract and protocol checks can establish instruction composition, not real-model obedience or live runtime behavior. Isolated model-driven replay and host integration remain separate evidence.

## Stable release

Maintainer-approved promotion of v31.22 from beta. The README is a short entry page: the semantic pack establishes a task from an ordinary user request and evidence before choosing implementation steps. Detailed architecture, inventories, references and model notes moved into `docs/technical-overview.md`. This does not reduce the authority/evidence safeguards that govern underspecified requests.

Both installer receipts now record `v31.22`; the prior `v30.87 beta` text was stale installer metadata. Pack-root detection now recognizes versioned v31 roots for safe upgrades, with isolated installer regression coverage. The terminal diagnostic is no longer described as temporary beta instrumentation. No new agent role, skill, execution permission, or gate is introduced.

Stable is the maintainer's release designation. Static contract checks and local package verification do not establish comparative model-quality or performance gains.
