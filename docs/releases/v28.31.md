# v28.31 release notes

v28.31 closes a freshness gap in read-only/current-issue analysis. Mutation and PR flows already refreshed Git provenance, but a read-only issue check could still inspect an old local checkout and incorrectly describe it as current upstream.

## Authoritative target before current-state claims

When the task asks about **current upstream/default/base behavior**, the active primary/orchestrator now resolves the actual authoritative remote ref from project guidance, host metadata, or tracking state, fetches it, records its SHA, and compares it with local HEAD before delegating analysis. There is no universal `upstream/main` assumption.

If the local checkout differs, the current-state conclusion must come from the fetched authoritative ref, not from local files. Local code can still be used as historical/comparison evidence.

## One freshness fetch, not one per specialist

Leaf `explore`/review/audit/test roles are not required to fetch independently. The orchestrator passes `<target_ref> @ <sha>` when a delegated assignment must make a current-upstream claim. If that context is missing or freshness is unknown, the specialist reports the gap instead of silently treating local HEAD as current.

## Fetch is not pull

A read-only freshness check may use `git fetch --prune <target_remote>` because it refreshes refs/metadata without updating the checked-out branch/worktree. `pull`, rebase, reset, or checkout are not required merely to inspect current upstream code.

## Issue verification

`/bug-issue` now resolves the report target before verification, and issue-originated bugfix flows establish the same freshness before diagnosis/mutation. Reports about current upstream/default/base are checked against the freshly fetched authoritative ref; reports explicitly about the local workspace use the local workspace and do not fetch by ritual.

## Unchanged behavior

- v28.29 tester batching/cadence is unchanged.
- v28.28 review-before-push Candidate semantics are unchanged.
- v28.30 failed-fix, decision-batching, and output rules are unchanged.
- No agent modes/permissions, skill payloads, OCR policy, or PR lifecycle were broadened.
