# v30.00-beta10 — restore stable role-local orchestrator routing

v30.00-beta10 is a narrow behavioral regression fix over beta9. The beta9 deduplication pass replaced the explicit leaf-role routing map inside `agents/code-orchestrator.md` with an abstract reference to root §5. Model testing on a read-only issue-analysis workflow showed that this weakened the independently active orchestrator prompt: the orchestrator correctly remembered that it owned evidence reconciliation, but then used its read access to perform repository tracing itself instead of routing the evidence-gathering stage to `@explore`.

## Restored local routing

`code-orchestrator` again carries an explicit role-local stage map:

- discovery / architecture tracing / finding the relevant path → `@explore`;
- confirmed root-cause bug fix → `@debugger`;
- focused non-bug, non-UI implementation → `@build`;
- focused, already-understood UI/web implementation → `@ui-implementer`;
- UI/web design, audit, redesign, unresolved direction, or coordinated multi-stage UI workflow → `@ui-orchestrator`;
- independent verification / explicit read-only reproduction / regression evidence → `@tester`;
- code/diff/PR/security/right-level review → `@reviewer`;
- Docker/systemd/CI/deploy/runtime work → `@devops`;
- architecture/multi-file/data/API/deployment planning with material alternatives or invariant-model escalation → `@plan`;
- bounded fallback research → `@general`.

The existing no-recursive-`@code-orchestrator`, `@general` fallback, and delegated UI depth rules remain.

## Discovery cadence remains unchanged

This release does **not** revert the v28.29 stage-economy improvement. A separate `@explore` stage is still not required merely because an implementation role does not yet know the exact file or symbol. `@debugger`, `@build`, or the applicable UI implementation role may inspect nearby code inside an already bounded assignment.

Use a separate `@explore` stage when:

- the target/scope is materially broad or ambiguous;
- multiple subsystems or ownership candidates must be mapped before a safe boundary can be established; or
- discovery / architecture tracing is itself the requested deliverable.

That last case is what the regression test exposed: an issue-review prompt explicitly requested code/tests/call-site/data-flow/ownership tracing and independent repository evidence. The orchestrator should normalize the issue contract and reconcile the resulting evidence, while `@explore` owns that repository-tracing stage.

## State identity is not duplicated

Beta9's `Current-state and mutation identity` / root §8.1 contract remains the single source for authoritative target/ref/SHA freshness. This release does not add a second provenance rule to the orchestrator. The issue-analysis test also exposed a separate state-identity mistake, but the existing beta9 contract already covers it.

## Deduplication lesson

Future semantic-deduplication must compare more than text similarity. A repeated rule is removable only when its **meaning, consumer, timing, and decision ownership** are all equivalent. Root routing is needed before role selection; the orchestrator-local map is needed after `code-orchestrator` has been selected and must choose a leaf stage. Those are different consumers/times, so both copies are intentional.

## Scope

Runtime change from beta9 is intentionally limited to the `Semantic routing` block in `agents/code-orchestrator.md`. README, changelog, and this release note are version/documentation updates only. No role mode/permission, skill, installer, command/snippet surface, gate, provenance rule, verification cadence, or PR lifecycle is changed.
