# v30.97 beta — conditional terminal diagnostic residency

## Summary

v30.97 removes the temporary terminal `session-evaluator` handoff procedure from every resident `code-orchestrator` session. The orchestrator keeps only a terminal-success activation hook; the new non-autoinvoked `terminal-semantic-eval` skill owns the one-time evaluator handoff and diagnostic non-gating semantics.

Permissions/frontmatter and bundled third-party/vendor skill content are intentionally unchanged.

## Ownership and residency split

- `code-orchestrator` — establishes the task/resource terminal state independently, then conditionally loads `terminal-semantic-eval` before final reporting.
- `terminal-semantic-eval` — terminal activation boundary, known-session-ID handoff, no ritual history discovery, and diagnostic-only/non-gating consumption.
- `session-evaluator` — post-hoc semantic/compliance diagnosis of completed orchestrated work.
- `session-evidence` — session retrieval/completeness mechanics only.

The evaluator cannot establish Ready/completion and its failure/unavailability cannot invalidate an already-established terminal state.

## Evaluation changes

- semantic ownership moves `terminal_session_evaluator_handoff` to the conditional skill;
- runtime residency adds the `terminal-diagnostic` audience and rejects terminal handoff procedure copied back into the resident orchestrator;
- ST-136 covers non-terminal non-activation/conditional residency;
- ST-137 covers diagnostic non-gating semantics.

Fresh isolated behavioral replay of ST-136..ST-137 is not claimed in this release, so v30.97 remains beta.
