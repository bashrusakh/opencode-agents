# v30.96 beta — conditional code-host resource residency

## Summary

v30.96 applies the residency rule one layer below the global root: resource-specific PR/issue/release procedure no longer stays resident in every `code-orchestrator` session. A new non-autoinvoked pack-owned `code-host-workflow` loads only when normalization selects a code-host resource deliverable.

Permissions/frontmatter and bundled third-party/vendor skill content are intentionally unchanged.

## Ownership and residency split

- `workflow-entry` — generic primary routing, user authorization/publication gate, provenance binding, visual-publication fallback and final workflow reporting.
- `code-orchestrator` — accountable engineering owner plus a short conditional discriminator: code-host resource selected -> load `code-host-workflow`.
- `code-host-workflow` — existing-PR host preflight/findings, issue deduplication/creation boundary, release/host publication mechanics, host template/metadata lookup and resource-specific result fields.
- `pr-readiness` — canonical Owned PR definition and Draft/Candidate/Ready lifecycle only.
- `git-provenance` — ref/SHA/worktree/base identity.
- `output-formatting` — destination formatting; `resource-lifecycle` — temporary-resource reconciliation.

Ordinary bugfix, tests/docs-only, local implementation and generic-review workflows do not load the code-host contract merely because a remote repository host exists.

## Control-plane changes

`runtime-residency-audit` now supports a `code-host-resource` audience and `forbidden_activator_families`. The release therefore fails if PR/issue/release/template procedure is copied back into resident `code-orchestrator`, if the new skill becomes auto-invokable, if its activation discriminator disappears, or if required host semantics are lost from the conditional owner.

`semantic-ownership-spec.json` moves the former issue/PR workflow family to `code-host-workflow`, adds release mechanics to that owner, redirects Owned-PR consumption through the resource skill, and guards pack-owned skills against becoming a second code-host workflow owner.

## Evaluation changes

- ST-122 is refined from role-resident adjacency to one conditional code-host resource owner.
- ST-134 — ordinary code workflows must not load code-host procedure.
- ST-135 — code-host workflow composes with `pr-readiness`/`git-provenance` instead of absorbing their state machines.
- destructive release probes cover autoinvoke, unconditional activation, PR/issue/release/template procedure leakage, under-preservation, PR-lifecycle duplication and pack-skill second ownership.

Fresh isolated behavioral replay of ST-134..ST-135 is not claimed in this release, so v30.96 remains beta.
