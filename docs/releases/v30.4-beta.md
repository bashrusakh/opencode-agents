# v30.4 beta — compact resident root, conditional policy skills

This beta fixes a root-policy size regression without weakening behavior. `AGENTS.md` had grown to 75,493 bytes after routing, cleanup, PR lifecycle, verification, and visual-evidence mechanics were made resident. The pack now returns to the intended architecture: critical semantic invariants stay resident; detailed conditional procedures load through native bundled skills only when their trigger applies.

## Root vs conditional policy

Root keeps: authority/gates, role/capability boundaries, request normalization, routing/execution-topology invariants, delegation monotonicity, fallback rules, mutation baseline requirement, evidence-freshness invariant, resource ownership/reconciliation states, repository-state identity, publication gates, and final-claim rules.

Detailed mechanics moved to bundled skills:

- `git-provenance` — worktree/branch/base/upstream/PR-head identity and mutation/publication checkpoints;
- `pr-readiness` — owned-PR Draft/candidate/review/push/CI/Ready mechanics;
- `verification-strategy` — verification cadence, evidence freshness, and blocked-check handling;
- `resource-lifecycle` — teardown/reconciliation procedure for temporary worktrees, branches, processes, evidence files, and hosted resources;
- `output-formatting` — detailed destination-specific public Markdown guidance.


## Loader guarantee

Each moved policy has an explicit activation condition in root. The existing global/project installers already copy complete `skills/` directories into OpenCode runtime, so no separate docs loader or project-root documentation mutation is required. Missing a required skill is not implicit permission; the root skill contract requires loading the selected skill or reporting it unavailable.

## Compatibility

- All 15 role files are unchanged from the preceding beta.
- Agent `mode` and permission frontmatter are unchanged.
- No new delegation edges or fallback rules.
- v30.2 cleanup outcomes and remote-deletion gates are unchanged.
- v30.1 routing/gate/plan-path semantics are unchanged.
