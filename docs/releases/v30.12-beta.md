# v30.12 beta

Context-hygiene integration built on v30.11 beta.

## Why

Long agentic sessions can accumulate completed tool I/O and settled-stage history that competes with the active task for working context. A fixed cadence would turn compaction into ceremony, while a command-first rule would confuse the context-hygiene goal with one particular mechanism.

## Changes

- Adds a root **context-pressure condition** defined by observable working-context pressure, not elapsed time or turn count.
- Adds bundled `magic-compact` workflow skill with explicit activation from the root skill catalog.
- Separates the goal (restore usable active context while preserving material state/authority/evidence) from the path (`magic-trim`, `magic-compact`, or no reduction).
- Prefers `magic-trim` when bulky completed tool I/O is the main pressure; uses full compaction only when broader settled conversational history materially contributes to pressure and a natural semantic boundary exists.
- Keeps unresolved reasoning, authority/provenance, state identity, pending/failed tool activity, and materially exact evidence out of unsafe compaction boundaries.
- Handles OpenCode capability honestly: use a native executable command surface when one exists; otherwise request the exact user-entered slash command instead of claiming the agent ran it.
- Adds `docs/magic_compact_setup.md` with an agent-safe installation/update procedure that checks the local OpenCode CLI contract before choosing syntax and treats external plugin installation/configuration as gated tooling mutation.

## Packaging

Magic Compact itself remains an external plugin and is **not vendored or silently installed** by the agent-pack installers. The package adds the runtime skill and setup reference; normal global/project installers already copy bundled skills automatically.

## Non-goals

- No fixed context-token/turn/time threshold.
- No background/polling compaction loop.
- No automatic cache deletion.
- No change to role capability boundaries, delegation topology, PR/readiness policy, or model/provider selection.
