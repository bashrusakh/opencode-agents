# v30.99 beta — cross-surface reference integrity after root residency split

## Summary

v30.99 is a reference-integrity correction over v30.98. It does not change permissions, vendor skills, role topology, or workflow ownership. It fixes resident role/pack-skill references that still named semantic owners from the pre-residency root layout.

The release adds an executable cross-surface reference gate so future owner/residency moves cannot leave a role pointing at a removed root section or at a semantic family now owned by a conditional skill.

## Runtime corrections

- `debugger` no longer cites removed root §7; its delegated boundary points to root §2.4 and implementation mechanics to `implementation-contract`.
- Startup/Update, routing map, fallback, review cadence, and user-gate references now point to `workflow-entry` / `delegation-control` rather than the universal root.
- direct current-upstream/default/base freshness references in `auditor`, `explore`, and `reviewer` now point to `git-provenance`.
- delegated mutation roles consume caller-established authorization/action ceilings instead of pretending they load the primary-only workflow-entry gate.
- `ui-component-sources` uses the caller-established workflow-entry/user-gate boundary rather than a stale generic root-gate alias.

## Evaluation

`reference-integrity-audit.py` scans every role and every pack-controlled skill surface. It checks that explicit numeric root-section references resolve in the current `AGENTS.md` and rejects known legacy semantic-owner aliases after residency moves. Vendor-advisory skill content is intentionally excluded from this normalization gate.

The v30.98 candidate contains 15 findings under this audit; the v30.99 candidate contains zero. Full release gates pass after the correction. Fresh isolated behavioral replay of the previously unreplayed ST-138..ST-141 set is still not claimed, so this release remains beta.
